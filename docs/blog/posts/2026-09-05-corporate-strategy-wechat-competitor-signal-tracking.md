# 企业战略团队如何监测竞品公众号动态：新品、人事与融资信号采集

做战略规划或竞争情报的团队,每个季度都要回答同一类问题:竞品最近发布了什么新产品?核心团队有没有人事变动?有没有新的产能布局或合作公告?这些信号很少出现在公开财报里,反而经常第一时间发在竞品自己的微信公众号上——一条新品预告、一次组织架构调整的内部信通稿、一个产业园区奠基仪式的报道,往往就是几个月后市场动作的前兆。

问题是,这类信息目前基本靠人工盯守:战略分析师在几个、十几个竞品公众号之间来回切换,逐篇打开、逐篇摘录,再手动整理进周报或季度竞对分析文档。这套流程有三个明显的短板。第一是**发现滞后**:公众号没有推送提醒机制,除非天天主动去翻,否则一条关键信号可能过去一两周才被注意到,等分析师察觉时,市场上可能已经有了后续动作。第二是**信息碎片化**:摘录散落在各人的笔记、聊天记录和 Excel 里,新人接手竞对分析时找不到历史脉络,同一个竞品的信号追踪很容易出现断档。第三是**缺少可检索的沉淀**:季度复盘想回顾"竞品 A 半年内发过几次产能扩张相关的内容",往往只能翻聊天记录或凭记忆,没有一份可以直接搜索、按时间线回放的原始素材库。

这三个短板的根源是一样的:竞品公众号的内容从始至终只以"网页文章"的形式存在,没有被转成结构化、可检索、可编程处理的数据。只要这一步没有解决,盯守动作就永远只能靠人眼和记性。

## 解决思路:把竞品公众号变成结构化数据源

[Mp2RSS](https://mp2rss.bugcode.dev) 把公众号内容处理成可编程的数据源:贴入任意一篇竞品公众号文章的链接(形如 `https://mp.weixin.qq.com/s?...`),即可订阅该文章所属的整个公众号;此后该号发布的每篇新文章都会被持续收录,正文以 **Markdown** 结构化形式交付,从发文到数据可见平均 **2–3 小时**。登录使用 GitHub / Google 账号,不涉及企业或个人微信账号,适合团队公用账号统一管理订阅清单。

对战略团队来说,这意味着竞对追踪可以拆成两层:**采集层交给系统**——批量订阅需要盯守的竞品官方号、创始人个人号、子品牌号,新文章自动进入数据流;**研判层留给人**——分析师只在信号出现或例行复盘时介入解读,不再花时间做重复的翻找和摘录。

## 落地步骤

### 第一步:建立竞品清单并批量订阅

先梳理需要覆盖的公众号范围,通常不止一个竞品官方号,还包括:竞品的子品牌号、创始人或高管的个人公众号(常用来发内部信、战略解读)、竞品所在集团的官方号(集团层面的产能、融资公告经常先发在这里)。找到每个号任意一篇文章的链接贴入 Mp2RSS 控制台即可完成订阅,不需要知道公众号的内部 ID,具体操作参考[订阅管理指引](/guide/subscription)。

如果需要覆盖的号数量较多,批量订阅可以用 [Open API](/api/) 脚本化完成:

```bash
curl -X POST "https://mp2rss.bugcode.dev/open-api/subscriptions" \
  -H "Authorization: Bearer {feed_key}" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://mp.weixin.qq.com/s?__biz=..."}'
```

需要提醒的是,首次订阅不会回溯历史文章,只从订阅时刻起收录该号后续发布的新文章。因此建立竞对监测项目时,越早完成订阅越好,避免错过订阅前的历史信号窗口。

### 第二步:按信号类型给文章打标签

竞对分析真正需要的不是"竞品发了一篇文章"这个事实,而是这篇文章属于哪一类业务信号。定时调用文章列表接口拉取增量文章,正文以 Markdown 字段返回,可以直接跑关键词规则或送入 LLM 做分类:

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

常见的分类维度包括:新品发布与功能更新、人事与组织架构变动、产能与基建投入、对外合作与生态动作、财务与融资相关表述。因为正文已经是干净的 Markdown、不含页面样式与广告位噪声,无论是写几十行关键词匹配脚本,还是直接把全文喂给 LLM 做摘要与分类,都可以省掉一轮网页解析和清洗的工作量。不想写代码的团队,也可以先用命令行工具 `mp2rss` 把文章拉到本地做初步筛选,安装与使用方式见 [CLI 文档](/cli/)。

### 第三步:沉淀为可检索的竞对档案库

分类后的文章按竞品、按信号类型、按时间线归档,就形成了一份可以直接检索的竞对档案库——不再依赖某个分析师的记忆或聊天记录里的截图。季度复盘时可以直接按竞品名和信号类型筛选,回看半年或一年内的动作节奏,判断某类信号(比如密集的产能相关文章)是否预示着即将到来的市场动作。这份档案库同时也是新人接手时最快的上手材料,不需要靠老同事口述交接竞对历史。

## 人工盯守与数据管道对比

| 维度 | 人工盯守竞品公众号 | 结构化数据管道 |
| ---- | ---- | ---- |
| 覆盖范围 | 精力有限,通常只能盯几个重点号 | 可批量订阅,覆盖官方号、子品牌号、高管个人号 |
| 发现时延 | 数天到数周,依赖主动翻阅 | 平均 2–3 小时 |
| 信息沉淀 | 分散在个人笔记与聊天记录 | 结构化 Markdown 正文,统一可检索 |
| 复盘效率 | 需要重新翻找与回忆 | 按竞品与信号类型直接筛选时间线 |

## 常见问题

**需要绑定竞品公众号或自己的企业微信账号吗?**
不需要。Mp2RSS 使用 GitHub / Google 账号登录,订阅动作只需要一篇目标公众号的文章链接,全程不涉及微信账号。

**订阅之后能看到竞品过去发过的历史文章吗?**
不能。首次订阅不回溯历史文章,只从订阅时刻起持续收录该号后续发布的新文章,建议竞对监测项目启动时尽早完成订阅,避免错过历史信号窗口。

**从竞品发文到我方能查到,大概要等多久?**
平均 2–3 小时。对季度复盘和多数战略决策场景来说,这个时延足以支撑分析师在信号出现后的当天或次日就介入研判。

**一个团队账号能同时订阅多少个竞品相关的号?**
按套餐档位区分:49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个,功能权益一致仅订阅上限不同,具体见[会员与计费](/guide/membership)。覆盖官方号、子品牌号、高管个人号等多个信源时,可以按需要覆盖的竞品数量选择合适档位。

**除了公众号,还能跟踪竞品在其他平台的动态吗?**
支持订阅 X(Twitter)账号,交付形态与公众号一致,可以并入同一套信号采集与归档管道,不需要为不同信源分别维护单独的流程。
