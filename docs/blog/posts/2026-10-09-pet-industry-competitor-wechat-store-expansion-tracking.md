# 宠物行业竞品情报人员如何监测同行公众号：新品上市与门店拓展追踪法

在宠物医院连锁、宠物店或宠物食品品牌做市场、拓展或运营工作的人员,经常需要回答类似的问题:同城同行这个月又在哪些商圈新开了门店?某款主力猫粮或驱虫产品的会员价相比上一次活动有没有调整?同行新上线的洗护套餐或体检套餐具体包含哪些项目?这些信息很少出现在同行的官网或平台店铺首页,反而经常先由其微信公众号发布——一篇新店开业推文、一篇会员日优惠海报、一篇新品上架通知,往往就是同行拓店节奏与定价策略变动最早的公开信号。

问题是,这类信息目前大多依赖人工盯守。拓展或市场岗位的同事需要在多家同行的总部号、门店号之间来回切换,逐篇打开、逐篇截图,再整理进内部竞品对比表或周度拓店会议材料。这套流程有两个明显的短板。第一是**发现滞后**:公众号没有订阅提醒机制,除非每天主动翻阅,否则一次悄然开业的新店或限时秒杀活动可能过去数天才被注意到,而宠物行业的会员日、节庆促销往往集中在短短几天内完成转化,跟进晚一步基本就错过了对应的排期和应对窗口。第二是**缺少结构化沉淀**:某家同行过去几轮拓店节奏、促销力度与新品定价散落在不同人的截图和聊天记录里,新同事接手某家竞品档案时很难快速理清脉络,拓店复盘会上也只能凭记忆拼凑时间线。

这两个短板的根源相同:同行公众号的内容始终只以网页文章的形式存在,没有转成结构化、可检索、可编程处理的数据。只要这一步没有解决,市场和拓展人员就只能靠人眼和记性去追踪同行的门店与价格节奏。

## 解决思路:把同行公众号变成结构化数据源

[Mp2RSS](https://mp2rss.bugcode.dev) 把公众号内容处理成可编程的数据源:贴入同行品牌公众号任意一篇文章的链接(形如 `https://mp.weixin.qq.com/s?...`),即可订阅该文章所属的整个公众号;此后该号发布的每篇新文章都会被持续收录,正文以 **Markdown** 结构化形式交付,从发文到数据可见平均 **2–3 小时**。登录使用 GitHub / Google 账号,不涉及企业或个人微信账号,适合市场或拓展岗位用统一账号管理需要长期覆盖的同行信源清单。

对宠物行业的市场和拓展人员来说,这意味着追踪工作可以拆成两层:**采集层交给系统**——批量订阅需要覆盖的同行总部号与各地门店号,新文章自动进入数据流;**研判层留给人**——市场或拓展同事只在关键信号出现或例行复盘时介入解读,不再花时间做重复的翻找和截图。

## 落地步骤

### 第一步:梳理同行信源并批量订阅

先确定需要覆盖的公众号范围,通常包括:重点对标的全国连锁总部号、意向拓店城市的区域运营号(新店开业与本地促销往往先由区域号发布)、以及重点自有品牌食品或用品的产品号。找到每个号任意一篇文章的链接贴入 Mp2RSS 控制台即可完成订阅,具体操作参考[订阅管理指引](/guide/subscription)。

需要覆盖的号数量较多时,批量订阅可以用 [Open API](/api/) 脚本化完成:

```bash
curl -X POST "https://mp2rss.bugcode.dev/open-api/subscriptions" \
  -H "Authorization: Bearer {feed_key}" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://mp.weixin.qq.com/s?__biz=..."}'
```

需要提醒的是,首次订阅不会回溯历史文章,只从订阅时刻起收录该号后续发布的新文章。因此建立某家同行的门店与定价追踪档案时,越早完成订阅越好,避免错过订阅前的历史开店记录与促销价格。

### 第二步:按信号类型抓取与分类

市场和拓展人员真正需要的不是"同行发了一篇文章"这个事实,而是这篇文章属于哪一类信号。定时调用文章列表接口拉取增量文章,正文以 Markdown 字段返回,可以直接跑关键词规则或送入 LLM 做分类:

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

常见的分类维度包括:新店开业与选址商圈、新品上架与配方说明、会员日与节庆促销价格、洗护体检套餐内容调整、加盟招商政策变化。因为正文已经是干净的 Markdown、不含页面样式与广告位噪声,无论是写关键词匹配脚本按"新店""会员价""秒杀""加盟"等关键词过滤,还是直接把全文喂给 LLM 做摘要与分类,都可以省掉一轮网页解析和清洗的工作量。不想写代码的团队,也可以先用命令行工具 `mp2rss` 把文章拉到本地做初步筛选,安装与使用方式见 [CLI 文档](/cli/)。

### 第三步:沉淀为可检索的竞品追踪库

分类后的文章按品牌、按城市、按信号类型归档,就形成了一份可以直接检索的同行门店与价格追踪库——不再依赖某位同事的记忆或聊天记录里的截图。拓店或市场会议复盘时可以直接按城市或信号类型筛选,回看某家同行从新店选址到历次会员价调整、促销节奏的完整时间线,判断本品牌的拓店计划与定价策略是应该加速跟进还是保持观望。这份追踪库同时也是新同事接手某家同行竞品档案时最快的上手材料。

## 常见问题

**需要绑定同行品牌的公众号或自己的企业微信账号吗?**
不需要。Mp2RSS 使用 GitHub / Google 账号登录,订阅动作只需要一篇目标公众号的文章链接,全程不涉及微信账号。

**订阅之后能看到同行品牌过去发过的历史开店与促销文章吗?**
不能。首次订阅不回溯历史文章,只从订阅时刻起持续收录该号后续发布的新文章,建议追踪某家同行的门店与价格动态时尽早完成订阅,避免错过订阅前的历史记录。

**从同行品牌发文到我方能查到,大概要等多久?**
平均 2–3 小时。对多数会员日活动跟进和例行拓店复盘场景来说,这个时延足以支撑市场或拓展人员在信号出现后的当天就介入研判。

**一个团队账号能同时订阅多少个同行相关的号?**
按套餐档位区分:49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个,功能权益一致仅订阅上限不同,具体见[会员与计费](/guide/membership)。覆盖多家连锁总部号、多个城市门店号与多个自有品牌产品号时,可以按需要覆盖的信源数量选择合适档位。

**除了公众号,还能跟踪同行品牌在其他平台的动态吗?**
支持订阅 X(Twitter)账号,交付形态与公众号一致,可以并入同一套信号采集与归档管道,不需要为不同信源分别维护单独的流程。
