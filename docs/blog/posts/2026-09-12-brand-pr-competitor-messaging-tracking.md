# 品牌公关团队如何监测竞品公众号对外发声：话术素材库搭建方法

品牌公关团队每天都要回答一类问题：竞品这次是怎么表态的？行业出现某个热点事件时，对方的官方号用了什么措辞回应？新一轮营销战役的 slogan 和传播角度是什么？这些信息很少出现在竞品的财报或官网首页，而是第一时间发布在其微信公众号——服务号的通稿、CEO 或公关负责人的个人号、区域子品牌号，往往才是对外口径的第一落点。

现实中，这类监测大多靠人工完成：公关同事在几个、十几个竞品公众号之间来回切换，看到相关文章就截图存进聊天记录或收藏夹。这套办法有明显的短板。第一是**响应窗口短却发现慢**：公众号没有推送提醒，热点事件发生后对方几个小时内就可能发文表态，如果不是恰好那个时间点在刷手机，往往等到同事转发才注意到，留给己方制定应对话术的时间已经被压缩。第二是**素材无法复用**：这次危机应对写得好的措辞、上次周年庆通稿的结构，全靠个人记忆或翻聊天记录去找，换了负责人交接时基本等于从零开始。第三是**缺少可检索的历史口径**：想回顾"竞品过去半年在环保议题上一共表态过几次、用词有没有变化"，除了逐条翻历史消息，没有更快的办法。

这三个短板的根源相同：竞品公众号的对外发声始终只是一篇篇网页文章，没有被转成结构化、可检索、可归类的数据。只要这一步没解决，公关团队就只能靠人眼盯守和个人记忆。

## 把竞品发声转成可检索的结构化数据

[Mp2RSS](https://mp2rss.bugcode.dev) 把公众号内容处理成可编程的数据源：贴入任意一篇竞品公众号文章的链接（形如 `https://mp.weixin.qq.com/s?...`），即可订阅该文章所属的整个公众号；此后该号发布的每篇新文章都会被持续收录，正文以 **Markdown** 结构化形式交付，从发文到数据可见平均 **2–3 小时**。登录使用 GitHub / Google 账号，不涉及微信账号，方便公关团队用公用账号统一管理监测清单。

对公关团队来说，这意味着竞品发声监测可以拆成两层：**采集与归档交给系统**——批量订阅需要盯守的竞品官方号、高管个人号、子品牌号，新文章自动进入数据流；**判断与应对留给人**——公关同事只在文章出现或需要复盘时介入解读，不必再花时间做重复的翻找和截图。

## 落地步骤

### 第一步：建立竞品发声监测清单

先梳理需要覆盖的公众号范围，通常不止竞品的官方服务号一个，还包括：CEO 或公关负责人的个人公众号（危机应对与行业表态经常先在这里出现）、区域或子品牌号（本地化传播话术的第一落点）、竞品所在集团的官方号。找到每个号任意一篇文章的链接贴入 Mp2RSS 控制台即可完成订阅，不需要知道公众号的内部 ID，具体操作参考[订阅管理指引](/guide/subscription)。

需要提醒的是，首次订阅不会回溯历史文章，只从订阅时刻起收录该号后续发布的新文章。因此监测清单越早建立越好，避免等到需要引用某次危机应对话术时，才发现订阅晚了没能收录进去。

### 第二步：用 Open API 批量订阅并拉取话术文本

监测号较多时，可以用 [Open API](/api/) 脚本化完成订阅，鉴权方式为 Bearer Token（控制台的 Feed 密钥）：

```bash
curl -X POST "https://mp2rss.bugcode.dev/open-api/subscriptions" \
  -H "Authorization: Bearer $FEED_KEY" \
  -H "Content-Type: application/json" \
  -d '{"articleUrl": "https://mp.weixin.qq.com/s/xxxxxxxxx"}'
```

订阅完成后，定时拉取该号的文章列表，正文以 `contentMarkdown` 字段返回：

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles?page=1&pageSize=100" \
  -H "Authorization: Bearer $FEED_KEY"
```

拿到的正文已经是干净的 Markdown，不含公众号页面的样式、广告位、图片懒加载占位符，可以直接送入关键词匹配脚本或喂给 LLM 做摘要与分类，省掉一轮网页解析和排版清洗。不想写脚本的团队，也可以用命令行工具 `mp2rss` 在本地定时拉取指定公众号的最新文章，安装与使用方式见 [CLI 文档](/cli/)。

### 第三步：按话术类型标注，沉淀素材库

公关团队真正需要的不是"竞品发了一篇文章"这个事实，而是这篇文章属于哪一类对外发声。常见的分类维度包括：危机应对与舆情回应措辞、campaign slogan 与广告语、新品发布通稿的表态角度、周年庆或合作公告的模板化措辞、行业热点事件的官方回应口径。把拉取到的文章按这些维度打标签后归档，就形成了一份可以直接检索的话术素材库——下次准备类似场景的应对稿时，可以先查竞品过去是怎么表态的，作为文案起草的参考背景，而不是从空白页开始想措辞。

### 第四步：接入告警，缩短反应窗口

对时效敏感的场景（例如行业突发热点事件），把订阅的 RSS/Atom Feed 接入企业微信机器人或飞书群告警规则，竞品官方号一旦发文，团队可以在平均 2–3 小时内看到内容，而不是等同事在群里转发截图才注意到。这段提前量对公关团队制定差异化表态、避免措辞撞车或跟风感，往往是决定性的。

## 人工盯守与数据管道对比

| 维度 | 人工盯守竞品公众号 | 结构化数据管道 |
| ---- | ---- | ---- |
| 覆盖范围 | 精力有限，通常只能盯几个重点号 | 可批量订阅，覆盖官方号、高管个人号、子品牌号 |
| 发现时延 | 依赖同事转发或主动翻阅，常滞后数小时到数天 | 平均 2–3 小时 |
| 素材沉淀 | 散落在截图和聊天记录里 | 结构化 Markdown 正文，按话术类型归档 |
| 复盘效率 | 需要重新翻找与回忆 | 按竞品与话术类型直接筛选时间线 |

## 常见问题

**订阅竞品公众号需要绑定微信账号吗？**
不需要。Mp2RSS 使用 GitHub / Google 账号登录，订阅动作只需要一篇目标公众号的文章链接，全程不涉及微信账号。

**订阅之后能看到竞品过去发过的历史发声吗？**
不能。首次订阅不回溯历史文章，只从订阅时刻起持续收录该号后续发布的新文章。如果计划长期跟踪某个竞品的对外表态，建议尽早完成订阅，避免错过订阅前的历史话术窗口。

**从竞品发文到我方能查到，大概要等多久？**
平均 2–3 小时。这个时延对多数公关决策场景（起草回应稿、准备内部简报）是够用的，不构成"秒级"或实时保证。

**一个团队账号能同时监测多少个竞品相关的号？**
按套餐档位区分：49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个，三档功能权益一致，仅订阅上限不同，具体见[会员与计费](/guide/membership)。覆盖官方号、高管个人号、子品牌号等多个信源时，可以按需要监测的竞品数量选择合适档位。

**除了公众号，还能跟踪竞品在其他平台的发声吗？**
支持订阅 X（Twitter）账号，交付形态与公众号一致，可以并入同一套话术采集与归档管道，不需要为不同信源分别维护单独的流程。
