# 快消品牌竞品情报人员如何监测同行公众号：新品上市与大促价格追踪法

在快消品或新消费品牌做市场情报、产品运营或电商策划的同事,大概都遇到过这样的场景:大促节点临近,老板突然问一句"竞品这次预售价定在多少?满减规则和我们比谁更划算?",而答案往往需要现场翻手机才能给出。新品预告、大促预售价、满减门槛、赠品政策这些关键信息,很少第一时间出现在竞品的电商店铺公告里,反而经常先由品牌自己的微信公众号发布——一篇新品种草推文、一篇"618 提前购"预告、一篇会员专属券后价通稿,往往就是价格战和上新节奏最早暴露的信号。

问题是,这类信息目前大多依赖人工盯守。市场情报或电商策划岗位的同事需要在几十个竞品品牌号、渠道号、代言人官方号之间来回切换,逐篇打开、逐篇截图,再手动整理进内部价格监测表。这套流程有两个明显的短板。第一是**发现滞后**:公众号没有订阅提醒机制,除非每天主动刷屏,否则竞品在大促预售期悄悄放出的"限时加赠"信息可能过去一两天才被注意到,而定价和促销跟进往往需要在预售开闸的当天就拿出对策,滞后的信息基本失去决策价值。第二是**缺少结构化沉淀**:某个竞品单品过去几次大促的预售价、满减门槛、赠品变化散落在不同人的截图和聊天记录里,新同事接手大促复盘时很难快速理清某个品类过去一年的价格走势,只能凭记忆拼凑时间线。

这两个短板的根源相同:竞品公众号的内容始终只以网页文章的形式存在,没有转成结构化、可检索、可编程处理的数据。只要这一步没有解决,情报团队就只能靠人眼和记性去追踪新品与价格节奏。

## 解决思路：把竞品公众号变成结构化数据源

[Mp2RSS](https://mp2rss.bugcode.dev) 把公众号内容处理成可编程的数据源:贴入竞品公众号任意一篇文章的链接(形如 `https://mp.weixin.qq.com/s?...`),即可订阅该文章所属的整个公众号;此后该号发布的每篇新文章都会被持续收录,正文以 **Markdown** 结构化形式交付,从发文到数据可见平均 **2–3 小时**。登录使用 GitHub / Google 账号,不涉及企业或个人微信账号,适合情报团队用统一账号管理需要覆盖的竞品信源清单。

对快消与新消费品牌的情报团队来说,这意味着追踪工作可以拆成两层:**采集层交给系统**——批量订阅需要覆盖的竞品品牌号、渠道号、联名或代言人相关的官方号,新文章自动进入数据流;**研判层留给人**——电商策划或定价同事只在大促预售开闸、关键信号出现或例行复盘时介入解读,不再花时间做重复的翻找和截图。

## 落地步骤

### 第一步：梳理竞品信源并批量订阅

先确定需要覆盖的公众号范围,通常包括:直接竞品的品牌官方号、竞品在电商渠道运营的渠道号(不少大促预售价先在渠道号里预告)、以及与竞品有联名合作或代言合作的关联号。找到每个号任意一篇文章的链接贴入 Mp2RSS 控制台即可完成订阅,具体操作参考[订阅管理指引](/guide/subscription)。

需要覆盖的号数量较多、或希望在大促前一次性把全品类竞品补齐时,批量订阅可以用 [Open API](/api/) 脚本化完成:

```bash
curl -X POST "https://mp2rss.bugcode.dev/open-api/subscriptions" \
  -H "Authorization: Bearer {feed_key}" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://mp.weixin.qq.com/s?__biz=..."}'
```

需要提醒的是,首次订阅不会回溯历史文章,只从订阅时刻起收录该号后续发布的新文章。因此计划追踪某次大促(比如双 11 或 618)的价格节奏时,越早完成订阅越好,避免错过预售期前的历史优惠与预告记录。

### 第二步：按信号类型抓取与分类

情报团队真正需要的不是"竞品发了一篇文章"这个事实,而是这篇文章属于哪一类信号。定时调用文章列表接口拉取增量文章,正文以 Markdown 字段返回,可以直接跑关键词规则或送入 LLM 做分类:

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

常见的分类维度包括:新品预告与卖点公布、预售价与券后价披露、满减门槛与叠加规则、限时加赠与赠品变化、直播间专属价。因为正文已经是干净的 Markdown、不含页面样式与广告位噪声,无论是写关键词匹配脚本按"预售""满减""券后价""加赠"等关键词过滤,还是直接把全文喂给 LLM 做摘要与分类,都可以省掉一轮网页解析和清洗的工作量。不想写代码的团队,也可以先用命令行工具 `mp2rss` 把文章拉到本地做初步筛选,安装与使用方式见 [CLI 文档](/cli/)。

### 第三步：沉淀为可检索的大促价格追踪库

分类后的文章按竞品品牌、按单品、按大促节点归档,就形成了一份可以直接检索的竞品新品与价格节奏追踪库——不再依赖某位同事的记忆或聊天记录里的截图。大促复盘时可以直接按单品筛选,回看该品类过去几次大促从预告、预售价到最终券后价、赠品政策的完整时间线,判断本方下一轮定价和满减规则应该跟进还是差异化。这份追踪库同时也是新同事接手某个品类竞品档案时最快的上手材料。

## 常见问题

**需要绑定竞品品牌的公众号或自己的企业微信账号吗?**
不需要。Mp2RSS 使用 GitHub / Google 账号登录,订阅动作只需要一篇目标公众号的文章链接,全程不涉及微信账号。

**订阅之后能看到竞品品牌过去发过的历史推文吗?**
不能。首次订阅不回溯历史文章,只从订阅时刻起持续收录该号后续发布的新文章,建议在大促预售期开始前尽早完成订阅,避免错过预售前的历史优惠与预告记录。

**从竞品发文到我方能查到,大概要等多久?**
平均 2–3 小时。对多数大促跟进决策和例行复盘场景来说,这个时延足以支撑情报团队在信号出现后的当天就介入研判。

**一个团队账号能同时订阅多少个竞品相关的号?**
按套餐档位区分:49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个,功能权益一致仅订阅上限不同,具体见[会员与计费](/guide/membership)。覆盖多家竞品品牌号、渠道号与联名关联号时,可以按需要覆盖的信源数量选择合适档位。

**除了公众号,还能跟踪竞品在其他平台的动态吗?**
支持订阅 X(Twitter)账号,交付形态与公众号一致,可以并入同一套信号采集与归档管道,不需要为不同信源分别维护单独的流程。
