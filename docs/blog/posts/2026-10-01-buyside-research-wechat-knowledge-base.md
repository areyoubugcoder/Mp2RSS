# 买方研究员如何搭建公众号投研素材库：跨行业信息归档与检索方法

买方机构的研究员很少只盯一个行业。覆盖范围调整、轮动研究、临时交叉验证某个论点，都要求研究员随时能从多个行业里调出相关信息。公众号是这些信息的重要来源之一——产业链上下游的自媒体账号、行业专家的个人号、第三方数据机构的解读文章，往往比正式研报更早、更细地描述一个产业的真实变化。

问题是这些内容几乎都是「读完就过」的。某篇文章在半年前读过，当时觉得有用，收藏后再没打开过；等到现在要写一份新的行业报告，想引用当时的某个数据或判断，却只记得「好像在哪个号上看到过」，具体是哪篇、哪天发的，已经完全想不起来。公众号本身不支持全文检索，收藏夹里积累几百篇文章之后，翻找的成本会迅速超过重新上网搜索的成本——但很多一手信息根本搜不到，因为它从一开始就只存在于那篇公众号文章里。

更现实的问题是覆盖范围的扩大。一个研究员从单一行业转向多行业覆盖后，需要跟踪的公众号数量可能从十几个涨到上百个，分布在完全不同的产业链环节。单纯靠人工打开公众号、下拉刷新去获取更新，很快会变成不可持续的体力活，最终被迫收窄关注范围，牺牲的是覆盖的广度和信息的时效性。

## 投研素材库和普通「收藏」的区别

对买方研究来说，素材库不是简单地把文章存起来，至少要满足三个条件：

1. **按行业和主题分类可检索**：换覆盖方向时，能快速调出某个行业过去一段时间的全部相关素材，而不是在一个大杂烩收藏夹里人工翻；
2. **正文可全文搜索**：很多时候记得的是某个具体的数据、某句判断，而不是标题，需要能按正文关键词命中；
3. **持续自动累积**：覆盖的行业和账号一旦确定，后续更新应该自动流入素材库，不需要每天手动巡查几十个公众号。

这三点决定了单纯依赖公众号自带的收藏功能或者手动截图保存，很难支撑起跨行业、长周期的投研工作。

## 解决思路：把公众号订阅变成结构化数据流

[Mp2RSS](https://mp2rss.bugcode.dev) 把公众号文章转换为结构化数据：把任意一篇目标公众号历史文章的链接（形如 `https://mp.weixin.qq.com/s?...`）贴入即可完成订阅，此后该账号新发布的文章会被持续采集，带着 Markdown 格式的正文沉淀下来，从发文到数据可见平均 2–3 小时。订阅不需要微信账号，用 GitHub 或 Google 账号登录即可使用。

对研究员来说，这相当于把「每天巡查几十上百个公众号」这件机械性工作交给系统持续运行，人力只在真正需要检索、引用或做跨行业对比时介入，而不必时刻在场盯着时间线刷新。

## 落地步骤

### 第一步：按覆盖行业梳理账号清单

把当前覆盖和潜在覆盖的行业分别列出来，每个行业下再细分信源类型，例如：

- **产业链自媒体**：上下游环节的从业者或垂直媒体账号；
- **第三方数据与渠道调研号**：发布草根调研、渠道价格、出货数据的账号；
- **行业专家 / 分析师个人号**：独立于所在机构、长期输出个人观点的账号。

按行业分组清单，后续无论是扩大覆盖还是临时切换研究方向，都能直接定位到对应的素材集合，而不是在一份扁平列表里逐一辨认。

### 第二步：批量完成订阅

账号数量不多时，可以按清单逐个在网页端订阅，具体操作参考[订阅管理指引](/guide/subscription)。覆盖的行业和账号较多时，用 [Open API](/api/) 批量提交会更高效，例如：

```bash
curl -X POST "https://mp2rss.bugcode.dev/open-api/subscriptions" \
  -H "Authorization: Bearer {feed_key}" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://mp.weixin.qq.com/s?__biz=..."}'
```

需要注意，首次订阅不会回溯该公众号此前发布的历史文章，只从订阅时刻起持续收录新内容。因此覆盖一个新行业时，建议第一时间把核心账号订阅完成，越早订阅，素材库在这个行业上积累的时间跨度就越完整。

### 第三步：定时拉取，按行业归档到本地或内部系统

订阅完成后，可以定时调用文章列表接口，把新增文章按行业分类拉取下来：

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

拿到的正文是 Markdown 格式，可以直接按行业建文件夹存放，也可以写入内部的研究知识库系统做统一检索。不想写代码对接接口的研究员，也可以直接使用 [CLI 工具（mp2rss）](/cli/)，用命令行完成订阅与拉取，省去额外的开发环节。

### 第四步：用大模型辅助初筛和要点提取

素材库积累到一定规模后，逐篇精读不现实。可以把新拉取的 Markdown 正文批量喂给大模型，做要点摘要、关键数据提取或与已有研究框架的相关性打分，先筛出当下真正需要精读的文章，其余留存归档、后续按需检索即可。这一步能显著缩短「大量素材」到「可直接用于写报告的要点」之间的处理时间。

### 第五步：跨行业检索与复用

真正的价值体现在跨行业对比和历史复用上：写一份新行业的覆盖启动报告时，可以先检索素材库里该行业过去几个月的全部存量信息，快速搭建认知框架；做产业链上下游联动分析时，也可以同时检索相关几个行业的素材做交叉验证。如果研究团队本身在搭建内部的检索系统或接入大模型做辅助问答，公众号数据同样可以作为标准化的可编程数据源接入，具体方式可参考[快速开始](/guide/quick-start)。

## 效果对比

| 维度 | 人工浏览 + 收藏夹 | 结构化投研素材库 |

## 常见问题

**订阅一个公众号需要对方授权吗？**
不需要。Mp2RSS 采集的是公众号公开发布的文章内容，只要有该公众号任意一篇文章的链接即可完成订阅，不涉及账号授权环节。

**能补录订阅之前该公众号已发布的历史文章吗？**
不能。首次订阅不会回溯历史文章，只从订阅时刻起持续收录新内容，因此覆盖新行业或新账号时建议尽早完成订阅。

**一个账号最多能同时追踪多少个公众号？**
按套餐档位区分：49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个，功能权益一致，仅订阅上限不同，详见[会员与计费](/guide/membership)。

**除了微信公众号，还能追踪境外信源吗？**
支持订阅 X（Twitter）账号，做跨境产业链或海外同行动态对比研究时，可以把两类信源并入同一条采集管道统一管理。

**拿到的数据能直接对接内部的研究系统吗？**
可以。交付形态包括 RSS 2.0 / Atom 1.0 / JSON Feed 1.1 / OPML 2.0，也提供 Open API（JSON 格式，Bearer 鉴权）和 CLI 工具，文章正文为 Markdown 格式，方便对接内部知识库或自建的检索、分析系统。
