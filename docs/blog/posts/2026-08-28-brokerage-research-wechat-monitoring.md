# 投研人员如何批量跟踪券商研报公众号：从人工刷屏到结构化研报库

二级市场的研究员和买方分析师，工作日的第一件事通常是打开微信，逐个点开几十个券商研究所的公众号——策略、行业、个股点评，各家研究所几乎都会在开盘前后集中发布当日观点。有人会把常看的号置顶到一个专门的文件夹，但即便如此，翻完一轮也要花不少时间，还要在过程中判断哪些标题值得点开细看。

更麻烦的是留存。看完一篇研报，想在几天后回头找某个观点的原文措辞，往往只能凭记忆在聊天记录或收藏夹里翻找；如果当时随手转发到了群里，原文的图表和排版还可能因为转发而丢失格式。跨账号跨设备查看，登录态和消息同步也常常掉链子。

对需要横向比较多家研究所观点、或者把研报内容并入自己研究笔记库的人来说，这种依赖人工翻阅和记忆的流程很难规模化——号越关注越多，漏看和检索成本就越高。

## 问题的核心：研报公众号没有可编程的读取方式

行业媒体、企业公众号、研究所公众号，本质上都是同一类内容形态：定期更新的图文文章。但微信公众号平台没有对外提供订阅或抓取接口，第三方工具也无法直接把公众号内容接入 RSS 阅读器、Obsidian 笔记库或自建的研究数据库。这就是为什么“多号盯盘”至今仍是体力活。

## 解决路径：把研报公众号变成结构化数据流

[Mp2RSS](https://mp2rss.bugcode.dev) 是一个微信公众号文章数据服务：贴入目标公众号任意一篇文章的链接（形如 `https://mp.weixin.qq.com/s?...`），即可订阅该公众号，此后它发布的每一篇新文章都会被持续收录，转换成**带 Markdown 正文的结构化数据**，从发文到数据可见平均 2–3 小时。使用时无需微信账号、无需扫码，用 GitHub 或 Google 账号登录即可。

订阅完成后，研报内容不再是「需要主动去看的消息」，而是变成一份可以随时检索、按时间线排列的数据。

## 落地步骤

### 第一步：整理关注清单并逐一订阅

先列出常看的研究所公众号，也可以按行业分组（策略、大金融、消费、科技等），便于后续区分信息流。对每个号，找到其任意一篇历史文章的链接，在 Mp2RSS 控制台贴入即可完成订阅，具体操作参考[订阅管理指引](/guide/subscription)。需要注意的是，首次订阅不会回溯该号此前发布的历史文章，只从订阅时刻起持续收录新文章，因此建议尽早把常看的号一次性订阅完。

关注的号较多时，也可以用 [Open API](/api/) 批量提交：

```bash
curl -X POST "https://mp2rss.bugcode.dev/open-api/subscriptions" \
  -H "Authorization: Bearer {feed_key}" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://mp.weixin.qq.com/s?__biz=..."}'
```

把每个研究所号的文章链接依次替换进去执行，几十个号的订阅可以在几分钟内完成，不需要逐个在网页里操作。完整的接口参数与鉴权方式可以从[快速开始](/guide/quick-start)了解。

### 第二步：选一种适合自己的消费方式

不写代码也能用：把 Mp2RSS 提供的 RSS / Atom / JSON Feed 聚合地址粘贴进常用的 RSS 阅读器，几十个研究所号合并成一条按时间排序的信息流，开盘前刷一遍即可，不必再切换到微信逐个翻找。这条信息流同样可以导入 Obsidian、Notion 等笔记工具的 RSS 插件，让研报正文随抓取自动落进个人知识库，便于后续加标注和交叉引用。

需要程序化处理时，直接调用文章列表接口拉取增量文章，正文以 Markdown 返回，可以直接入库或送入下游流程：

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

### 第三步：按行业或标的做二次归类

研报正文是 Markdown 格式，标题、要点、评级等结构化内容都能被程序解析。可以按标题关键词（行业名、个股名称、评级用语）做简单的规则匹配，把研报自动归入对应的分类目录或打上标签，形成一份按行业、按标的检索的研报库，而不是一堆按时间堆叠的原始消息。对于需要横向比较多家观点的场景，这份结构化研报库比逐条翻聊天记录效率更高。

## 效果对比

| 维度 | 人工逐号翻阅 | 结构化数据流 |
| ---- | ---- | ---- |
| 覆盖号数 | 受个人精力限制 | 可批量订阅数十个号 |
| 更新感知 | 依赖主动打开查看 | 从发文到数据可见平均 2–3 小时 |
| 内容留存 | 转发易丢格式，检索靠记忆 | Markdown 正文全文可检索 |
| 归类方式 | 手工分类或不分类 | 可按关键词自动打标签 |

## 常见问题

**订阅一个研究所公众号需要知道它的公众号 ID 吗？**
不需要。只要有该号任意一篇文章的链接（`https://mp.weixin.qq.com/s?...`），贴入即可完成订阅，系统会自动识别所属公众号。

**能看到订阅之前发布的历史研报吗？**
首次订阅不回溯历史文章，只从订阅时刻起持续收录新发布的内容，因此建议提前把常看的号订阅完毕，避免错过后续发布。

**一个账号能同时订阅多少个研究所公众号？**
按套餐档位区分：49 元/月支持 50 个订阅、99 元/月支持 100 个、399 元/月支持 400 个，各档位功能权益一致，仅订阅数量上限不同，详见[会员与计费](/guide/membership)。

**除了公众号研报，还能一并跟踪机构在其他平台发布的内容吗？**
支持订阅 X（Twitter）账号，同样以结构化数据交付，可以和公众号研报并入同一条信息流或同一个研究库。

**需要用微信账号登录才能使用吗？**
不需要。Mp2RSS 使用 GitHub 或 Google 账号登录，订阅与抓取过程都不涉及你的微信账号。
