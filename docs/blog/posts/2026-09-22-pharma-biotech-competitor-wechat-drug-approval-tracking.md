# 医药行业情报人员如何监测竞品药企公众号：新药获批与临床进展追踪法

在医药和生物科技行业做市场准入、BD 或战略情报的人员,每天都要回答类似的问题:竞品的某款在研药物临床进展到哪个阶段了?有没有新适应症获批上市?有没有在学术会议上公布新的临床数据?这些信息很少第一时间出现在药监部门的公开通告里,反而经常先由药企自己的微信公众号发布——一篇上市喜讯通稿、一篇临床数据解读、一篇高管在行业峰会上的演讲摘要,往往就是竞争格局变化的最早信号。

问题是,这类信息目前大多依赖人工盯守。情报或市场准入岗位的同事需要在几十个药企官方号、学术媒体号之间来回切换,逐篇打开、逐篇摘录关键信息,再整理进内部周报或竞品追踪表。这套流程有两个明显的短板。第一是**发现滞后**:公众号没有订阅提醒机制,除非每天主动翻阅,否则一条关键的适应症获批消息可能过去几天才被注意到,而医保准入、学术推广节奏往往就跟在获批消息后面几周内启动。第二是**缺少结构化沉淀**:某个竞品在研管线的进展记录散落在不同人的笔记和聊天记录里,新同事接手时很难快速理清某款药物过去一年的进展脉络,复盘时也只能凭记忆或翻找截图。

这两个短板的根源相同:竞品药企公众号的内容始终只以网页文章的形式存在,没有转成结构化、可检索、可编程处理的数据。只要这一步没有解决,情报人员就只能靠人眼和记性去追踪管线动态。

## 解决思路:把竞品药企公众号变成结构化数据源

[Mp2RSS](https://mp2rss.bugcode.dev) 把公众号内容处理成可编程的数据源:贴入竞品药企公众号任意一篇文章的链接(形如 `https://mp.weixin.qq.com/s?...`),即可订阅该文章所属的整个公众号;此后该号发布的每篇新文章都会被持续收录,正文以 **Markdown** 结构化形式交付,从发文到数据可见平均 **2–3 小时**。登录使用 GitHub / Google 账号,不涉及企业或个人微信账号,适合情报团队用统一账号管理订阅清单。

对医药情报团队来说,这意味着追踪工作可以拆成两层:**采集层交给系统**——批量订阅需要覆盖的竞品官方号、旗下产品线子品牌号、行业学术媒体号,新文章自动进入数据流;**研判层留给人**——医学事务或市场准入同事只在关键信号出现或例行复盘时介入解读,不再花时间做重复的翻找和摘录。

## 落地步骤

### 第一步:梳理竞品信源并批量订阅

先确定需要覆盖的公众号范围,通常包括:竞品药企的官方号、重点产品线的子品牌号(部分大适应症产品会单独开号做患者教育与学术推广)、以及覆盖该治疗领域的行业学术媒体号。找到每个号任意一篇文章的链接贴入 Mp2RSS 控制台即可完成订阅,具体操作参考[订阅管理指引](/guide/subscription)。

需要覆盖的号数量较多时,批量订阅可以用 [Open API](/api/) 脚本化完成:

```bash
curl -X POST "https://mp2rss.bugcode.dev/open-api/subscriptions" \
  -H "Authorization: Bearer {feed_key}" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://mp.weixin.qq.com/s?__biz=..."}'
```

需要提醒的是,首次订阅不会回溯历史文章,只从订阅时刻起收录该号后续发布的新文章。因此建立某款竞品药物的追踪项目时,越早完成订阅越好,避免错过订阅前的历史进展记录。

### 第二步:按信号类型给文章分类

情报团队真正需要的不是"竞品发了一篇文章"这个事实,而是这篇文章属于哪一类进展信号。定时调用文章列表接口拉取增量文章,正文以 Markdown 字段返回,可以直接跑关键词规则或送入 LLM 做分类:

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

常见的分类维度包括:适应症获批与上市信息、临床试验阶段性进展(如 III 期数据发布)、学术会议报告与专家访谈、医保准入或集采相关表述、患者教育与商业化动作。因为正文已经是干净的 Markdown、不含页面样式与广告位噪声,无论是写关键词匹配脚本,还是直接把全文喂给 LLM 做摘要与分类,都可以省掉一轮网页解析和清洗的工作量。不想写代码的团队,也可以先用命令行工具 `mp2rss` 把文章拉到本地做初步筛选,安装与使用方式见 [CLI 文档](/cli/)。

### 第三步:沉淀为可检索的管线追踪库

分类后的文章按竞品公司、按药物或适应症、按信号类型归档,就形成了一份可以直接检索的竞品管线追踪库——不再依赖某位同事的记忆或聊天记录里的截图。季度复盘时可以直接按药物名称筛选,回看过去半年内该产品从临床数据发布到正式获批的完整节奏,判断市场准入与商业化团队应该在什么时间点介入准备。这份追踪库同时也是新同事接手竞品档案时最快的上手材料。

## 常见问题

**需要绑定竞品药企的公众号或自己的企业微信账号吗?**
不需要。Mp2RSS 使用 GitHub / Google 账号登录,订阅动作只需要一篇目标公众号的文章链接,全程不涉及微信账号。

**订阅之后能看到竞品过去发过的历史文章吗?**
不能。首次订阅不回溯历史文章,只从订阅时刻起持续收录该号后续发布的新文章,建议追踪某款在研药物时尽早完成订阅,避免错过订阅前的历史进展记录。

**从竞品药企发文到我方能查到,大概要等多久?**
平均 2–3 小时。对多数市场准入决策和例行复盘场景来说,这个时延足以支撑情报人员在信号出现后的当天或次日就介入研判。

**一个团队账号能同时订阅多少个竞品相关的号?**
按套餐档位区分:49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个,功能权益一致仅订阅上限不同,具体见[会员与计费](/guide/membership)。覆盖多家竞品企业的官方号、子品牌号与学术媒体号时,可以按需要覆盖的信源数量选择合适档位。

**除了公众号,还能跟踪竞品在其他平台的动态吗?**
支持订阅 X(Twitter)账号,交付形态与公众号一致,可以并入同一套信号采集与归档管道,不需要为不同信源分别维护单独的流程。
