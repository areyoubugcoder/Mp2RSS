# 保险行业竞品情报人员如何监测同业保险公司公众号：新产品条款与费率调整追踪法

在保险公司做产品情报、渠道支持或精算配合工作的人员,经常需要回答类似的问题:某家同业这个季度新上了哪些重疾险或年金产品?某款热销产品的费率表相比半年前有没有调整?免责条款、等待期或犹豫期的表述是不是悄悄变了?这些信息往往不会第一时间出现在同业公司的官网产品页,反而经常先由其微信公众号发布——一篇新品上市推文、一篇条款升级说明、一篇费率调整通知,往往就是同业产品策略变动最早的公开信号。

问题是,这类信息目前大多依赖人工盯守。产品情报或渠道支持岗位的同事需要在几十个同业公司官方号、区域分支机构号、保险中介与经纪公司号之间来回切换,逐篇打开、逐篇摘录关键信息,再整理进内部产品对比表或月度简报。这套流程有两个明显的短板。第一是**发现滞后**:公众号没有订阅提醒机制,除非每天主动翻阅,否则一次悄然的费率上调或条款收紧可能过去数天才被注意到,而产品排期和渠道话术往往需要在同业动作公开后的一两天内就拿出应对方案,滞后太久基本就错过了跟进窗口。第二是**缺少结构化沉淀**:某家同业过去一两年内某条产品线的条款迭代、费率调整、停售与新品替代节奏散落在不同人的截图和文档里,新同事接手某个竞品档案时很难快速理清脉络,产品委员会复盘时也只能凭记忆拼凑时间线。

这两个短板的根源相同:同业公司公众号的内容始终只以网页文章的形式存在,没有转成结构化、可检索、可编程处理的数据。只要这一步没有解决,情报人员就只能靠人眼和记性去追踪产品与费率节奏。

## 解决思路:把同业公司公众号变成结构化数据源

[Mp2RSS](https://mp2rss.bugcode.dev) 把公众号内容处理成可编程的数据源:贴入同业公司公众号任意一篇文章的链接(形如 `https://mp.weixin.qq.com/s?...`),即可订阅该文章所属的整个公众号;此后该号发布的每篇新文章都会被持续收录,正文以 **Markdown** 结构化形式交付,从发文到数据可见平均 **2–3 小时**。登录使用 GitHub / Google 账号,不涉及企业或个人微信账号,适合情报岗位用统一账号管理需要长期覆盖的同业信源清单。

对保险行业情报人员来说,这意味着追踪工作可以拆成两层:**采集层交给系统**——批量订阅需要覆盖的同业总部号、区域分支机构号、保险经纪与中介机构号,新文章自动进入数据流;**研判层留给人**——产品或精算同事只在关键信号出现或例行复盘时介入解读,不再花时间做重复的翻找和摘录。

## 落地步骤

### 第一步:梳理同业信源并批量订阅

先确定需要覆盖的公众号范围,通常包括:重点对标同业公司的总部官方号、竞争激烈区域的分支机构号(区域性费率试点和限时加保政策往往先由分支号发布)、以及覆盖保险行业动态的经纪公司与行业媒体号。找到每个号任意一篇文章的链接贴入 Mp2RSS 控制台即可完成订阅,具体操作参考[订阅管理指引](/guide/subscription)。

需要覆盖的号数量较多时,批量订阅可以用 [Open API](/api/) 脚本化完成:

```bash
curl -X POST "https://mp2rss.bugcode.dev/open-api/subscriptions" \
  -H "Authorization: Bearer {feed_key}" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://mp.weixin.qq.com/s?__biz=..."}'
```

需要提醒的是,首次订阅不会回溯历史文章,只从订阅时刻起收录该号后续发布的新文章。因此建立某家同业的产品条款追踪项目时,越早完成订阅越好,避免错过订阅前的历史条款与费率变动记录。

### 第二步:按信号类型抓取与分类

情报人员真正需要的不是"同业发了一篇文章"这个事实,而是这篇文章属于哪一类信号。定时调用文章列表接口拉取增量文章,正文以 Markdown 字段返回,可以直接跑关键词规则或送入 LLM 做分类:

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

常见的分类维度包括:新产品上市与停售公告、费率表调整与加费说明、条款升级(等待期、免责范围、犹豫期表述变化)、限时加保与老客户权益活动、分支机构区域性促销政策。因为正文已经是干净的 Markdown、不含页面样式与广告位噪声,无论是写关键词匹配脚本按产品名称和"费率""条款""停售"等关键词过滤,还是直接把全文喂给 LLM 做摘要与分类,都可以省掉一轮网页解析和清洗的工作量。不想写代码的团队,也可以先用命令行工具 `mp2rss` 把文章拉到本地做初步筛选,安装与使用方式见 [CLI 文档](/cli/)。

### 第三步:沉淀为可检索的产品条款追踪库

分类后的文章按同业公司、按产品线、按信号类型归档,就形成了一份可以直接检索的同业产品条款追踪库——不再依赖某位同事的记忆或聊天记录里的截图。产品委员会复盘时可以直接按产品线筛选,回看某款重疾险或年金产品从上市公告到历次费率调整、条款迭代的完整时间线,判断本方产品排期和渠道话术是应该跟进调整还是保持观望。这份追踪库同时也是新同事接手某家同业档案时最快的上手材料。

## 常见问题

**需要绑定同业公司的公众号或自己的企业微信账号吗?**
不需要。Mp2RSS 使用 GitHub / Google 账号登录,订阅动作只需要一篇目标公众号的文章链接,全程不涉及微信账号。

**订阅之后能看到同业公司过去发过的历史产品与费率文章吗?**
不能。首次订阅不回溯历史文章,只从订阅时刻起持续收录该号后续发布的新文章,建议追踪某家同业的产品条款时尽早完成订阅,避免错过订阅前的历史条款与费率变动记录。

**从同业公司发文到我方能查到,大概要等多久?**
平均 2–3 小时。对多数产品跟进决策和例行复盘场景来说,这个时延足以支撑情报人员在信号出现后的当天就介入研判。

**一个团队账号能同时订阅多少个同业相关的号?**
按套餐档位区分:49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个,功能权益一致仅订阅上限不同,具体见[会员与计费](/guide/membership)。覆盖多家同业总部号与多个重点区域分支机构号时,可以按需要覆盖的信源数量选择合适档位。

**除了公众号,还能跟踪同业公司在其他平台的动态吗?**
支持订阅 X(Twitter)账号,交付形态与公众号一致,可以并入同一套信号采集与归档管道,不需要为不同信源分别维护单独的流程。
