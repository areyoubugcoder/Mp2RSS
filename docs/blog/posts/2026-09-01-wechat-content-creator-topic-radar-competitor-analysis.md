# 内容创作者如何用微信公众号数据搭建选题雷达：竞品追踪与热点素材库

做内容的人都熟悉这种焦虑：同一个话题,同行号已经发了三篇爆款,自己还在犹豫要不要跟。公众号生态里,选题的窗口期往往只有一两天——同行动作快,读者的注意力就转移得快。而大多数内容团队追踪同行的方式,仍然是编辑每天打开微信,逐个点开关注的号,手动记录标题和阅读量。

这种方式有明显的上限。人一天能盯的号有限,超过二三十个之后漏看是常态;记录方式通常是截图或手抄进文档,时间一长很难检索,想找「上个月同行写过哪些关于这个话题的文章」几乎无从下手;夜间和周末发布的内容更是大概率被错过——但热点往往不分工作时间。

选题雷达要真正起作用,前提是同行号的历史与新增内容都能以数据的形式沉淀下来,可以批量看、按关键词搜、按时间轴回溯,而不是散落在几十个人的记忆和聊天记录里。等到选题会上有人问「上次这个话题谁写过、写得怎么样」,靠翻聊天记录找,往往比重新写一篇原创还慢——素材没有沉淀下来,团队的选题经验也就没法真正积累。

## 解决思路:把同行号变成可检索的选题库

[Mp2RSS](https://mp2rss.bugcode.dev) 是一个微信公众号文章数据服务:找到一篇公众号文章的链接,贴进去即可订阅这个号,之后它发布的每一篇新文章都会被持续收录为**带 Markdown 正文的结构化数据**,从发文到数据可见平均 2–3 小时。登录不依赖微信账号,用 GitHub 或 Google 账号即可完成。

对内容团队来说,这意味着选题追踪可以拆成三层来做:

- **采集层**:批量订阅需要盯的同行号、行业媒体号、垂直大号,交给系统持续抓取;
- **检索层**:文章正文是结构化文本,可以按关键词、时间范围检索,快速回答「谁写过、什么时候写的、写了什么角度」;
- **产出层**:把检索到的素材整理成选题清单或热点简报,供编辑会参考。

## 落地步骤

### 第一步:梳理追踪清单并订阅

先列出需要持续关注的号,通常包括三类:直接竞品的官方号、同赛道头部内容号、上游行业媒体号。对每个号,拿到它任意一篇文章的链接(`https://mp.weixin.qq.com/s?...`),在 Mp2RSS 里贴入即可完成订阅,具体操作参考[订阅管理指引](/guide/subscription)。号数不多时手动订阅几分钟就能搞定;号数较多,可以用 [Open API](/api/) 批量执行:

```bash
curl -X POST "https://mp2rss.bugcode.dev/open-api/subscriptions" \
  -H "Authorization: Bearer {feed_key}" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://mp.weixin.qq.com/s?__biz=..."}'
```

需要注意的是,首次订阅不会回溯历史文章,只从订阅时刻起持续收录新内容——所以追踪清单越早建好,积累的选题素材就越完整。

### 第二步:选一种日常消费方式

不同团队规模适合不同接法:

- **个人或小团队**:直接把 Mp2RSS 提供的聚合 Feed(RSS 2.0 / Atom 1.0 / JSON Feed 1.1)订进常用的 RSS 阅读器,每天早会前扫一眼新文章列表,当作选题晨读;也可以导出 OPML 2.0 批量导入阅读器,不用逐个手动添加订阅源。
- **有编辑流程的团队**:定时调用文章列表接口拉增量,把标题和正文正文喂进选题会用的文档或飞书/Notion 表格:

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

正文以 Markdown 形式返回,直接粘贴进笔记工具或投喂给大模型做摘要都很方便,这一步也可以借助 [CLI 工具](/cli/)在本地脚本里完成拉取。

### 第三步:按关键词沉淀成热点素材库

选题雷达最终要解决的是「回溯」问题:某个话题过去两周同行写了几篇、切入角度分别是什么。做法很简单——把持续入库的文章按标题与正文关键词打标签,归入不同选题分类的文件夹或表格视图。积累几周后,编辑会前先搜关键词,就能快速看到同行在这个话题上的全部动作,而不必凭记忆。

对于经常需要追踪海外或英文信源的团队,同一套流程也支持订阅 X(Twitter)账号,中文行业号与英文信源可以并入同一个素材库,统一检索。这样一来,选题会不再需要提前几天临时抱佛脚地翻资料,而是随时能从积累的素材库里调出相关内容,新人接手追踪任务时也能直接沿用已有的素材分类,不必从零摸索该关注哪些号。

## 效果对比

| 维度 | 人工刷号选题 | 数据化选题雷达 |
| ---- | ---- | ---- |
| 覆盖号数上限 | 二三十个,靠个人精力 | 数百个,系统持续采集 |
| 历史可检索性 | 依赖记忆与截图 | 全文可关键词检索 |
| 感知时延 | 数小时到次日 | 平均 2–3 小时 |
| 夜间/周末覆盖 | 大概率遗漏 | 持续采集不间断 |

## 常见问题

**订阅一个公众号需要知道它的公众号 ID 吗?**
不需要。只要有这个号任意一篇文章的链接(`https://mp.weixin.qq.com/s?...`),贴入即可完成订阅,系统会自动识别归属的公众号。

**能追溯订阅之前同行号已经发过的历史文章吗?**
不能。首次订阅只从订阅时刻起收录新文章,不回溯历史,因此建议尽早把追踪清单里的号都订阅上。

**除了 RSS 阅读器,还有别的接入方式吗?**
提供 RSS 2.0、Atom 1.0、JSON Feed 1.1、OPML 2.0 等标准格式,也提供 Bearer 鉴权的 [Open API](/api/)和 [CLI 工具](/cli/),可以按团队习惯的工具链自由选择接入方式,新手可以先看[快速开始](/guide/quick-start)。

**一个账号能同时追踪多少个公众号?**
按套餐区分上限:49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个,不同档位功能一致,仅订阅数量上限不同,详见[会员与计费](/guide/membership)。

**只能追踪微信公众号吗?**
除公众号外,也支持订阅 X(Twitter)账号,可以把中英文信源纳入同一个选题素材库统一检索。
