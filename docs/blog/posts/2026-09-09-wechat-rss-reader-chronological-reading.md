# 摆脱微信公众号算法推荐：用 RSS 阅读器按时间线追更新的方法

打开微信「订阅号消息」列表，靠前的往往不是最新发布的文章，而是被算法判断为「你可能感兴趣」的内容。关注的号更新了，如果这段时间互动少，文章会被排到很靠后的位置，甚至几天之后才被刷到；而「看一看」信息流里混杂着好友在看、热点推荐和广告，想找一篇具体的更新，需要在无关内容里反复下拉。

对习惯用「关注列表」而不是「推荐流」获取信息的人来说，这种排序方式本身就是障碍：读者想要的是「谁发了新内容我就看到」，而不是「系统觉得我该看什么」。可惜公众号平台没有开放官方的时间线视图，也没有提供 RSS 输出——这是博客和新闻网站几乎标配的功能，公众号完全没有，读者只能被动接受一个不透明的排序逻辑，或者退回到逐个点开每个订阅号手动翻找的原始方式。

真正需要的是一条独立于算法之外的信息通道：关注的号发了新文章，就按时间顺序出现在自己选定的阅读工具里，不掺杂推荐、不看互动权重，读完即走，没读的也不会被排序逻辑埋没。

## 算法时间线带来的具体问题

- **更新可能被延迟看到**：排序基于互动预测而非发布时间，冷门号或近期互动少的号，更新会被排到很后面。
- **信息流里夹杂无关内容**：「看一看」混合好友动态、广告和热点推荐，找一篇具体更新需要额外筛选。
- **无法跨号统一时间线浏览**：关注的多个号只能逐个点进公众号主页翻看历史消息，没有一个按时间倒序汇总所有关注号更新的视图。
- **依赖微信客户端**：只能在手机或电脑端的微信里查看，无法用自己习惯的阅读工具（Reeder、NetNewsWire、Feedly、Inoreader 等）统一管理未读、标星或稍后处理。

这些问题的共同根源是：公众号文章从发布起就只活在微信生态内部，没有一个标准、开放的订阅协议（RSS/Atom）可以接入。

## 解决思路：把公众号转换成标准 RSS 订阅源

[Mp2RSS](https://mp2rss.bugcode.dev) 提供的是公众号文章的数据转换服务：把想跟踪的公众号的任意一篇文章链接（`https://mp.weixin.qq.com/s?...`）贴进去，就能订阅它所属的整个公众号；此后该号发布的每一篇新文章都会被持续收录，并生成标准的 RSS 2.0 / Atom 1.0 / JSON Feed 1.1 格式订阅源，从发文到数据可见平均 2–3 小时。使用时不需要绑定微信账号，用 GitHub 或 Google 账号登录即可完成注册。

有了标准 Feed，关注的公众号就能像博客、新闻站一样被任意一款 RSS 阅读器订阅，阅读顺序完全由发布时间决定，不再经过任何推荐算法的二次排序。

## 落地步骤

### 第一步：订阅想追踪的公众号

打开任意一篇属于该公众号的文章，复制链接贴入 Mp2RSS 控制台完成订阅，具体操作参见[订阅管理指引](/guide/subscription)。需要注意，首次订阅不会回溯历史文章，只从订阅时刻起收录新内容，所以真正想长期追更的号，建议现在就完成订阅，而不是等到想查旧文章时才想起来。

### 第二步：把 Feed 地址加入 RSS 阅读器

每个订阅都会生成一个独立的 Feed 地址，格式可选 RSS 2.0、Atom 1.0 或 JSON Feed 1.1。把这个地址粘贴进任意支持订阅源的阅读器（手机端如 Reeder、Fiery Feeds，桌面端如 NetNewsWire，跨平台如 Feedly、Inoreader），阅读器会按发布时间把所有关注号的更新汇总在同一条时间线里，未读、已读、加星标都由阅读器自己管理，和公众号内部的排序逻辑完全无关。这一步不需要写代码，是最快能感受到「按时间线阅读」体验的方式。

### 第三步：需要更细粒度控制时，用 Open API 拉取数据

如果 RSS 阅读器的展示形式不够用——比如想自己写一个按天分组的阅读列表，或者把更新推送到 Telegram / 邮件——可以直接调用 [Open API](/api/) 拉取结构化的文章数据：

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

返回结果带有标题、发布时间与 Markdown 正文，可以按发布时间排序后自行渲染成任何形式的时间线视图，不需要额外解析或抓取网页。习惯命令行操作的用户，也可以用 [CLI 工具](/cli/) 直接在终端里管理订阅、查看最新文章列表。

### 第四步：合并多个信息源到同一条时间线

如果除了公众号之外，还习惯关注一些 X（Twitter）账号获取信息，Mp2RSS 同时支持订阅 X 账号，推文与长文同样以结构化数据交付，可以并入同一个 Feed 聚合流程，不需要为不同平台维护两套阅读工作流。

## 常见问题

**需要绑定微信账号或用手机操作吗？**
不需要。Mp2RSS 用 GitHub 或 Google 账号登录，订阅和后续的 Feed 生成都不依赖微信客户端。

**只是想用手机上的 RSS 阅读器看更新，不想碰代码，可以吗？**
可以。把订阅生成的 RSS 或 JSON Feed 地址粘贴进阅读器 App 即可，Open API 和 CLI 只是给需要更细粒度控制的人多一个选项。

**能看到订阅之前该号发过的历史文章吗？**
不能。首次订阅只从订阅时刻起收录新文章，不会回溯历史，所以长期想追的号建议尽早订阅。

**除了公众号，还能把哪些内容源并入同一条时间线？**
同时支持订阅 X（Twitter）账号，推文和长文都能和公众号更新一起按时间线呈现。

**订阅的公众号数量有限制吗？**
有档位区分：49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个，功能完全一致，仅上限不同，详见[会员与计费](/guide/membership)。
