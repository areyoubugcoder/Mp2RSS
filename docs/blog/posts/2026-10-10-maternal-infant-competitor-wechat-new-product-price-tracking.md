# 母婴行业竞品情报人员如何监测同行公众号：新品配方与促销价格追踪法

在母婴用品品牌、奶粉厂商或母婴连锁门店做产品、市场或采购工作的人员,经常要回答类似的问题:同价位段的竞品奶粉这次换代配方具体改了什么、有没有新增认证?某款热销纸尿裤或辅食品牌的会员日价格相比上一轮活动有没有松动?同行新上线的孕产妇课程或育儿服务包里具体包含哪些项目?这些信息很少第一时间出现在天猫旗舰店或同行官网,反而经常先由其微信公众号发布——一篇配方升级的科普长文、一张会员日满减海报、一篇新品上市通知,往往就是同行产品节奏与定价策略变动最早的公开信号。

问题是,这类信息目前大多依赖人工盯守。产品或市场岗位的同事需要在多个品牌号、门店号、专家科普号之间来回切换,逐篇打开、逐篇截图,再整理进内部竞品对比表或新品评审材料。这套流程有两个明显的短板。第一是**发现滞后**:公众号没有订阅提醒机制,除非每天主动翻阅,否则一次配方升级发布或限时满赠活动可能过去数天才被注意到,而母婴行业的大促节点(年货节、六一、双十一、会员日)往往集中在短短几天内完成转化,跟进晚一步基本就错过了对应的排期和应对窗口。第二是**缺少结构化沉淀**:某个竞品过去几轮配方升级、认证背书与价格策略散落在不同人的截图和聊天记录里,新品评审会上只能凭记忆拼凑竞品的迭代时间线,难以支撑"这次该不该跟价"之类的决策。

这两个短板的根源相同:同行公众号的内容始终只以网页文章的形式存在,没有转成结构化、可检索、可编程处理的数据。只要这一步没有解决,产品和市场人员就只能靠人眼和记性去追踪竞品的配方与价格节奏。

## 解决思路:把同行公众号变成结构化数据源

[Mp2RSS](https://mp2rss.bugcode.dev) 把公众号内容处理成可编程的数据源:贴入竞品品牌公众号任意一篇文章的链接(形如 `https://mp.weixin.qq.com/s?...`),即可订阅该文章所属的整个公众号;此后该号发布的每篇新文章都会被持续收录,正文以 **Markdown** 结构化形式交付,从发文到数据可见平均 **2–3 小时**。登录使用 GitHub / Google 账号,不涉及企业或个人微信账号,适合产品或市场岗位用统一账号管理需要长期覆盖的竞品信源清单。

对母婴行业的产品和市场人员来说,这意味着追踪工作可以拆成两层:**采集层交给系统**——批量订阅需要覆盖的竞品品牌号、门店号与专家科普号,新文章自动进入数据流;**研判层留给人**——产品或市场同事只在关键信号出现或例行评审时介入解读,不再花时间做重复的翻找和截图。

## 落地步骤

### 第一步:梳理竞品信源并批量订阅

先确定需要覆盖的公众号范围,通常包括:直接对标的奶粉或纸尿裤品牌官方号(配方升级与新品上市大多先在官方号发布)、母婴连锁门店的区域运营号(促销活动与会员日价格往往由区域号推送)、以及品牌合作的育儿专家或科普号(认证背书与成分解读经常以科普长文形式出现)。找到每个号任意一篇文章的链接贴入 Mp2RSS 控制台即可完成订阅,具体操作参考[订阅管理指引](/guide/subscription)。

需要覆盖的号数量较多时,批量订阅可以用 [Open API](/api/) 脚本化完成:

```bash
curl -X POST "https://mp2rss.bugcode.dev/open-api/subscriptions" \
  -H "Authorization: Bearer {feed_key}" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://mp.weixin.qq.com/s?__biz=..."}'
```

需要提醒的是,首次订阅不会回溯历史文章,只从订阅时刻起收录该号后续发布的新文章。因此建立某个竞品的配方与价格追踪档案时,越早完成订阅越好,避免错过订阅前的历史配方迭代记录与大促价格。

### 第二步:按信号类型抓取与分类

产品和市场人员真正需要的不是"竞品发了一篇文章"这个事实,而是这篇文章属于哪一类信号。定时调用文章列表接口拉取增量文章,正文以 Markdown 字段返回,可以直接跑关键词规则或送入 LLM 做分类:

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

常见的分类维度包括:配方升级与新增认证、新品上市与规格调整、会员日及大促满减价格、孕产妇课程与育儿服务包内容变化、门店拓展与渠道合作动态。因为正文已经是干净的 Markdown、不含页面样式与广告位噪声,无论是写关键词匹配脚本按"配方""认证""满减""会员价"等关键词过滤,还是直接把全文喂给 LLM 做摘要与分类,都可以省掉一轮网页解析和清洗的工作量。不想写代码的团队,也可以先用命令行工具 `mp2rss` 把文章拉到本地做初步筛选,安装与使用方式见 [CLI 文档](/cli/)。

### 第三步:沉淀为可检索的竞品追踪库

分类后的文章按品牌、按信号类型归档,就形成了一份可以直接检索的竞品配方与价格追踪库——不再依赖某位同事的记忆或聊天记录里的截图。新品评审或定价会议上可以直接按品牌或信号类型筛选,回看某个竞品从配方升级、认证背书到历次大促价格的完整时间线,判断本品牌的新品节奏与定价策略是应该加速跟进还是保持观望。这份追踪库同时也是新同事接手某个竞品档案时最快的上手材料。

## 常见问题

**需要绑定竞品品牌的公众号或自己的企业微信账号吗?**
不需要。Mp2RSS 使用 GitHub / Google 账号登录,订阅动作只需要一篇目标公众号的文章链接,全程不涉及微信账号。

**订阅之后能看到竞品品牌过去发过的历史配方与促销文章吗?**
不能。首次订阅不回溯历史文章,只从订阅时刻起持续收录该号后续发布的新文章,建议追踪某个竞品的配方与价格动态时尽早完成订阅,避免错过订阅前的历史记录。

**从竞品品牌发文到我方能查到,大概要等多久?**
平均 2–3 小时。对多数大促活动跟进和新品评审场景来说,这个时延足以支撑产品或市场人员在信号出现后的当天就介入研判。

**一个团队账号能同时订阅多少个竞品相关的号?**
按套餐档位区分:49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个,功能权益一致仅订阅上限不同,具体见[会员与计费](/guide/membership)。覆盖多个竞品品牌官方号、多个区域门店号与多个合作科普号时,可以按需要覆盖的信源数量选择合适档位。

**除了公众号,还能跟踪竞品品牌在其他平台的动态吗?**
支持订阅 X(Twitter)账号,交付形态与公众号一致,可以并入同一套信号采集与归档管道,不需要为不同信源分别维护单独的流程。
