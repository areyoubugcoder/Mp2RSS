# 公众号更新转邮件简报：不用打开微信也能按天追更的工作流

有一类信息习惯很常见：不装额外的 App，所有需要处理的信息都走邮箱——工作邮件、Newsletter、提醒事项都在收件箱里按时间排好,处理完归档或删除,一个入口搞定。但公众号恰恰是这类工作流里的一个缺口:关注的号更新了只能在微信「订阅号消息」里看,没有办法像 Newsletter 一样自动落到收件箱,结果就是公众号内容永远要单独开一次微信才能看到,和其他信息源的处理节奏脱节。

更麻烦的是,公众号的「订阅号消息」列表本身也不完全按时间排序,互动少的号更新了容易被排到后面,想确认「今天这几个号有没有发新文章」,得逐个点进去翻。如果同时关注了十几个号,这个翻找过程每天都要重复一次,而翻找本身并不产生任何新信息,纯粹是时间消耗。

对这类用户来说,真正需要的不是一个「更好的公众号阅读器」,而是让公众号更新**用邮件的形式**出现在已经在用的收件箱里,和其他邮件一样可以搜索、加星标、用邮箱自带的规则自动分类到文件夹,不需要为了看几篇公众号文章单独切换到另一个 App。

## 邮箱处理信息流的人会遇到的具体问题

- **信息入口不统一**:工作邮件、Newsletter 走收件箱,公众号更新却只能在微信里看,处理节奏被打断,容易忘记查看。
- **没有官方的邮件订阅能力**:公众号平台不提供「关注即发邮件提醒」的功能,唯一的提醒方式是依赖微信自身的推送,而推送本身也受算法排序影响。
- **多号汇总依赖手动翻找**:关注的号越多,逐个确认「今天谁更新了」的操作就越重复,没有一份统一的「今日更新清单」。
- **历史记录不便检索**:微信内的文章消息很难用邮箱的搜索习惯去查找,想找「上个月那篇提到某个数据的文章」往往要靠记忆去翻聊天记录。

这些问题的共同根源还是公众号文章只活在微信生态内部,没有开放标准的订阅协议,自然也没有天然的邮件出口。

## 解决思路:先转换成标准 Feed,再用 RSS 转邮件工具接入收件箱

[Mp2RSS](https://mp2rss.bugcode.dev) 做的是公众号文章的数据转换:把想追踪的公众号的任意一篇文章链接(`https://mp.weixin.qq.com/s?...`)贴进去,就能订阅这个号,此后它发布的新文章都会被持续收录,并生成标准的 RSS 2.0 / Atom 1.0 / JSON Feed 1.1 格式订阅源,从发文到数据可见平均 2–3 小时。登录不需要绑定微信账号,用 GitHub 或 Google 账号即可完成。

有了标准 Feed,剩下的问题就变成了一个成熟的工具组合:把 Feed 地址交给任意一款「RSS 转邮件」服务或自建的邮件摘要工具,由它负责定时抓取 Feed、打包成一封邮件发到指定邮箱。这一步和公众号本身无关,是 RSS 生态里已经存在多年的标准做法,公众号只是作为一个普通的 RSS 源接入进去。

## 落地步骤

### 第一步:把要追踪的公众号转换成 Feed

打开想追踪的公众号的任意一篇文章,复制链接,贴入 Mp2RSS 完成订阅,具体操作参见[订阅管理指引](/guide/subscription)。需要注意,首次订阅不会回溯历史文章,只从订阅时刻起收录新内容,所以确定要长期追的号,建议现在订阅,不要等到想查旧文章时才想起来。

订阅完成后,在「账户设置」里能看到账户级别的 Feed 链接,默认会把所有已订阅的公众号(以及 X 账号)合并成一条统一的时间线,不需要为每个号单独维护一个邮件订阅。

### 第二步:选择一个 RSS 转邮件的接入方式

常见的做法有两类:

- **直接用 RSS 转邮件服务**:把 Mp2RSS 生成的 RSS 或 Atom 链接提交给这类服务,设置好「每天几点、汇总当天更新」,服务会定时抓取 Feed 内容并发一封邮件到指定邮箱。这一步不需要写代码,几分钟就能配置完成。
- **自建邮件摘要流程**:如果已经在用 n8n、Zapier 或类似的自动化工具搭建信息处理流程,可以直接把 RSS 节点指向同一个 Feed 链接,输出端接邮件发送动作,自定义邮件的标题格式、分组方式(比如按公众号分组,而不是简单按时间顺序列出)。

两种方式用的都是同一个 Feed 地址,区别只是「谁来负责定时抓取和拼邮件」,可以先用现成服务跑起来,之后有更细的格式需求再换成自建流程。

### 第三步:需要更细粒度的内容时,用 Open API 自己拼邮件正文

如果现成的 RSS 转邮件服务只能把标题和摘要塞进邮件,想要邮件里直接包含文章正文(方便在收件箱里完整阅读,不用再跳转原文),可以调用 [Open API](/api/) 拉取结构化数据:

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

返回结果带标题、发布时间和 Markdown 正文,可以在定时任务里把当天新增的文章渲染成一封邮件的 HTML 正文后发送,邮件内容和原文一致,不需要额外抓取网页或解析格式。习惯命令行操作的用户,也可以用 [CLI 工具](/cli/) 在脚本里直接拉取最新文章列表,再接入自己熟悉的发信方式。

### 第四步:把 X 账号的更新并入同一份简报

如果除了公众号之外,还习惯关注一些 X(Twitter)账号获取信息,Mp2RSS 同时支持订阅 X 账号,推文与长文同样以结构化数据交付,可以并入同一个账户级 Feed,邮件简报里自然就包含了公众号和 X 两类信息源,不需要为不同平台单独配置两套邮件流程。

### 第五步:用 OPML 做一次性迁移或备份

如果之前已经在某个 RSS 服务或阅读器里维护了一份公众号订阅列表,想统一挪到邮件简报流程里,可以直接导入 OPML 文件完成迁移,不需要逐个重新添加;反过来,也可以把 Mp2RSS 里的订阅导出成 OPML,作为邮件简报流程失效时的备份方案。

## 两种追更方式的对比

| 维度 | 微信订阅号消息 | 公众号转邮件简报 |
| ---- | ---- | ---- |
| 查看入口 | 必须打开微信 | 日常收件箱,和其他邮件一起处理 |
| 多号汇总 | 逐个号手动翻找 | 一封邮件统一列出当天更新 |
| 检索历史 | 依赖聊天记录翻找 | 用邮箱自带搜索,按关键词 / 发件人筛选 |
| 处理方式 | 仅能点开查看 | 可加星标、分文件夹、用邮箱规则自动归档 |
| 更新到账时间 | 不透明,可能延迟 | 平均 2–3 小时数据可见,邮件按设定频率发出 |

## 常见问题

**需要会写代码才能搭这个邮件简报流程吗?**
不一定。用现成的 RSS 转邮件服务,只需要把 Mp2RSS 生成的 Feed 链接填进去并设置发送频率,全程不需要写代码。只有想要邮件里包含完整正文、或者按自定义格式分组时,才需要用 [Open API](/api/) 或 [CLI 工具](/cli/) 写一小段脚本。

**能收到订阅之前该公众号发过的历史文章吗?**
不能。首次订阅只从订阅时刻起收录新文章,不会回溯历史,所以确定要长期追踪的号建议尽早订阅。

**一个 Feed 链接可以同时装进邮件简报和手机上的 RSS 阅读器吗?**
可以。Feed 地址本身是标准格式,邮件简报工具和普通阅读器可以同时订阅同一个链接,互不影响,适合「手机用阅读器刷,邮箱做归档备份」这类双轨使用习惯。

**除了公众号,邮件简报里还能放哪些内容?**
同时支持订阅 X(Twitter)账号,推文和长文都能和公众号更新合并进同一个账户级 Feed,邮件简报会自然包含两类信息源的更新。

**订阅的公众号数量有限制吗?**
有档位区分:49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个,功能完全一致,仅上限不同,详见[会员与计费](/guide/membership)。
