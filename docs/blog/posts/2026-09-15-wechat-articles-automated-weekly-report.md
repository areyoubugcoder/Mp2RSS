# 数据分析师如何把公众号数据自动生成行业监测周报：从采集到模板产出

很多公司的行业监测周报都是同一个流程：分析师周五下午打开几十个公众号，逐个翻看这一周有没有更新，把标题、发布时间、核心信息手动摘抄进一份 Word 或 PPT，再按行业动态、竞品动态、政策动态几个板块分类排版，发给管理层或业务部门。这个流程每周都要重复一遍，占用的往往是分析师最零碎、最容易出错的半天到一天时间。

更麻烦的是这类周报很难做到真正"不漏"。公众号更新没有固定节奏，有的号一周发三篇，有的号两周不发一篇突然连发五篇；人工刷号只能覆盖当下想起来要看的账号，稍微一忙就容易漏看某个号，等发现的时候周报已经发出去了，只能等下一期补充说明。周报的时效性也受限于人工整理的速度——从看到一篇关键文章到把它写进周报、发给相关人，中间往往隔了好几天。

分析师真正想做的其实不是"抄标题"这件事本身，而是把时间花在判断信息重要性、写解读和结论上。但只要数据采集和格式排版这两步没有自动化，抄标题的工作量就压缩不掉，分析产出的部分永远只能是剩下的时间。

## 问题的核心：周报的原材料没有结构化来源

微信公众号没有官方的订阅或抓取接口，公众号文章无法直接接入脚本或报告生成工具。这意味着即便报告的模板、分类逻辑、分发渠道都已经确定，只要"这一周有哪些新文章、分别是谁发的、写了什么"这一步仍然依赖人工打开公众号逐条查看，整个周报流程就没法真正自动化，只能停留在"人工采集 + 手动排版"的半自动状态。

## 解决路径：把公众号更新变成可以定期渲染的结构化数据

[Mp2RSS](https://mp2rss.bugcode.dev) 提供微信公众号文章的结构化数据服务：贴入目标公众号任意一篇文章的链接（形如 `https://mp.weixin.qq.com/s?...`），即可订阅整个账号，此后该账号发布的每一篇新文章都会被持续收录，转换成**带标题、发布时间、Markdown 正文的结构化数据**，从发文到数据可见平均 2–3 小时。注册不需要微信账号，用 GitHub 或 Google 账号登录即可。

一旦更新变成结构化数据，"生成周报"就可以拆成两个独立、都能自动化的环节：定期拉取本周新增文章，以及把这些数据按模板渲染成排版好的报告，两者都不再需要人工打开公众号本身。

## 落地步骤

### 第一步：批量订阅要纳入周报的公众号

先按周报覆盖的板块（行业媒体、竞品官号、监管或协会号等）列出账号清单，逐个找到一篇历史文章链接完成订阅，操作参考[订阅管理指引](/guide/subscription)。账号数量多时，用 [CLI](/cli/) 写一个循环批量订阅比逐个在网页操作快得多：

```bash
mp2rss auth login                              # 首次使用先登录
mp2rss mp subscribe https://mp.weixin.qq.com/s/xxxxxxxxxx
```

需要注意，首次订阅不会回溯该账号此前发布的历史文章，只从订阅时刻起持续收录新内容，所以周报覆盖的账号最好尽早订阅完，避免临到出周报那周才发现某个账号还没接入。完整的鉴权和调用方式见[快速开始](/guide/quick-start)。

### 第二步：定时拉取本周新增文章

周报的出报节奏一般是固定的（每周一或每周五），可以用 cron 或调度平台在固定时间触发一次拉取，按发布时间过滤出上一个周期新增的文章。用 [Open API](/api/) 按订阅账号逐个拉取：

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

也可以用 CLI 输出 JSON，配合 `jq` 按 `publishedAt` 过滤出本周区间的文章：

```bash
mp2rss mp articles {mpId} -o json \
  | jq '[.items[] | select(.publishedAt >= 本周起始时间戳)]' \
  > weekly_articles.json
```

返回数据里每篇文章都带 `title`、`publishedAt`、`contentMarkdown` 等字段，正文以 Markdown 交付，天然适合直接送入报告模板，不需要再做格式清洗。

### 第三步：按模板渲染成周报并自动分发

拉到本周增量数据后，用脚本按公众号或预设分类分组，套用固定的报告模板批量渲染。用 Python 读取上一步的 JSON，按账号分组后渲染成一份 Markdown 周报，是比较简单的落地方式：

```python
import json
from collections import defaultdict

with open("weekly_articles.json") as f:
    items = json.load(f)

grouped = defaultdict(list)
for item in items:
    grouped[item["mpName"]].append(item)

lines = ["# 行业监测周报\n"]
for mp_name, articles in grouped.items():
    lines.append(f"## {mp_name}")
    for a in articles:
        lines.append(f"- {a['title']}")
    lines.append("")

report = "\n".join(lines)
```

生成的 Markdown 已经是一份结构清晰的周报草稿，可以直接转成邮件正文、企业微信/飞书机器人消息，或用现成工具转成 Word/PDF 附件定时发出。分析师需要投入的精力回归到审阅本周有价值的内容、补充要点解读和结论，而不是从头核对本周哪些号发了新文章。

## 效果对比

| 维度 | 人工整理周报 | 结构化数据 + 模板渲染 |
| ---- | ---- | ---- |
| 覆盖账号数 | 受精力限制，容易漏看 | 可批量订阅并持续收录 |
| 数据来源到成稿 | 人工打开、摘抄、排版，耗时数小时 | 拉取数据后脚本自动渲染成稿，耗时以分钟计 |
| 出报节奏 | 依赖人工记得按时整理 | 可用定时任务固定周期触发 |
| 分析师精力分配 | 大量时间用于抄标题、排版 | 集中在解读与结论 |

## 常见问题

**周报模板需要每次手动改吗？**
不需要。报告模板（分类逻辑、排版结构）只需要设计一次，后续每次出报只是把新拉取的结构化数据套进同一个模板重新渲染，模板本身不用逐期调整。

**首次接入某个公众号能不能把过去几个月的文章都补进周报？**
不能。首次订阅只从订阅时刻起持续收录新发布的文章，不回溯历史内容，因此新纳入周报覆盖范围的账号建议尽早订阅，避免影响后续周期的完整性。

**除了公众号，还能把其他信源一起纳入同一份周报吗？**
支持同时订阅 X（Twitter）账号，同样以结构化数据交付，可以和公众号数据合并进同一套周报渲染流程。

**报告分发也能自动化吗，还是只能自动生成草稿？**
渲染出的 Markdown 或 JSON 数据可以直接对接邮件发送脚本、IM 机器人接口或文档转换工具，从数据拉取到最终发出可以做成一条完整的定时任务链路，不需要人工介入分发环节。

**一个账号最多能订阅多少个公众号用来做周报数据源？**
按套餐档位区分：49 元/月支持 50 个订阅、99 元/月支持 100 个、399 元/月支持 400 个，各档位功能一致，仅订阅数量上限不同，详见[会员与计费](/guide/membership)。
