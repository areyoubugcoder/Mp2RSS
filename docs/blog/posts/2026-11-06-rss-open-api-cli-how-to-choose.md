# RSS、Open API、CLI 怎么选？公众号与 X 内容接入决策指南

如果你的目标是在阅读器里追更，先选 RSS；如果要把内容接入自己的应用，选 Open API；如果习惯在终端工作，或者要让能执行命令的 Agent 读取内容，先用 CLI。选择入口时，最有用的问题是：**拿到内容后，谁来消费它，要完成什么任务？**

三个入口都依赖账户的订阅与权限。更换入口不会让尚未采集的文章立即出现，也不会绕过会员要求。开始前，在 [Mp2RSS 控制台](https://mp2rss.bugcode.dev)确认账户、订阅及有效会员状态；是否有试用以站内显示为准，具体规则见[会员与计费](/guide/membership)。

## 按任务选择入口

| 你的任务 | 优先入口 | 需要准备什么 | 首次成功的判断 |
| --- | --- | --- | --- |
| 在阅读器中集中阅读公众号与 X 更新 | RSS / Atom | 支持相应格式的阅读器、账户 Feed 链接 | 能打开目标源的一条真实内容 |
| 给自己的应用接入文章、推文或长文 | Open API | 能发 HTTP 请求的程序、Feed 密钥、已订阅源的 ID | 返回目标内容，并检查所需字段 |
| 在终端查询，或交给能运行命令的 Agent | CLI | CLI 运行环境、完成授权的账户 | 命令返回实际内容，来源与正文可核对 |

如果下游已经支持 JSON Feed，可以使用对应的 Feed 地址；这与 Open API 的接口、字段及调用方式不同。OPML 则用于导出和导入订阅目录，不是文章正文接口。

## 只想阅读：先跑通 RSS

阅读器已经承担列表展示、未读管理和定期刷新，你只需提供订阅地址。具体步骤是：

1. 在控制台订阅一个要跟踪的公众号或 X 账号。
2. 在账户设置中复制 Feed 链接，导入阅读器。
3. 刷新后打开一条目标来源的内容，核对标题或推文文本、发布时间与原文链接。

默认合集可以汇合公众号与 X 内容，适合把日常追更集中到一个入口。完整操作见[快速开始](/guide/quick-start)。

不要把“导入成功”当作“内容已取得”。刚建立订阅时可能没有可用内容；阅读器刷新、服务采集和来源发布也有各自的时间。会员提示条目属于服务通知，不能拿来证明已经读到信息源内容。

## 已有应用：用 Open API 接入结构化数据

当你需要按来源取内容、处理分页、保存字段或实现自己的展示界面时，Open API 更方便。程序使用 Feed 密钥作为 Bearer 凭据，按[接口文档](/api/)获取已订阅源及内容。

接入时先做一个小闭环：选定一个真实订阅，取少量内容，检查来源 ID、发布时间、原文链接与正文，再扩展到存储和后续处理。不要一开始就把“请求成功”转换成“文章已入库”的业务结论。

公众号文章与 X 长文可以返回 `contentMarkdown`，但正文可能为空；X 推文使用另一套字段，文本在 `content` 中。需要全文的任务必须检查正文是否存在，不能把标题或摘要当成完整文章输入。

如果应用需要持续运行，还应处理鉴权失败、会员到期、空列表和限流。收到限流响应时按照 `Retry-After` 等待，避免紧密重试。字段、分页和错误处理以当前接口文档为准。

## 终端与 Agent 工作：从 CLI 开始

CLI 适合先验证一个内容读取任务，再把命令接入自己的工作流程。已有 Node.js 与 pnpm 的环境，可以按以下顺序开始：

```bash
pnpm add -g @mp2rss/cli
mp2rss --help
mp2rss auth login
mp2rss mp list -o json
mp2rss x list -o json
```

这些列表命令用于取得自己已订阅源的 ID。下一步按[首次内容获取指南](/cli/first-delivery)读取一个源，确认返回正文与原文对应。示例是操作路径，不代表你当前账户已有订阅或内容。

交给 Agent 时，任务应说明“只总结实际返回的内容，附来源与发布时间，正文为空时报告缺失”。安装 CLI 或同步 Skill 成功，并不代表 Agent 已加载工具，更不代表内容读取成功。

## 公众号与 X 的操作边界

| 操作 | 公众号 | X |
| --- | --- | --- |
| 建立订阅 | 可在控制台操作，也可通过 Open API / CLI 使用文章链接订阅 | 在 Web 控制台搜索并订阅 |
| 程序读取 | 使用 `mpId` 读取文章 | 使用 `xUserId`，分别读取推文与长文 |
| 内容核对 | 标题、原文链接、发布时间与正文 | 推文文本和发布时间；长文另核对正文与链接 |

不要把 X 的用户名直接当作 `xUserId`，也不要期待 CLI 提供 X 搜索、订阅或取消订阅命令。账户的公众号与 X 订阅合并计入套餐上限，切换工具不会增加配额。

## 常见决策问题

### RSS 和 CLI 能同时用吗？

可以。你可以用阅读器追更，再用 CLI 处理某个具体任务。两者共用账户权限，Feed 密钥需要妥善保管。

### 改用 API 会获得更多历史内容吗？

不能据此保证。入口变化不代表采集范围扩大，首次订阅也不保证提供完整历史内容。

### 暂时不会编程，应该从哪里开始？

先用 RSS 完成一次真实阅读。明确需要保存哪些字段或做什么处理后，再评估 API 或 CLI。

### 工具选好了，但一直没有内容怎么办？

按[订阅成功却没有文章的排查流程](/blog/posts/2026-11-06-subscription-no-content-troubleshooting)定位停在哪一环，避免反复切换工具。
