# 跨境电商选品团队如何用公众号内容搭建趋势雷达：从追热点到量化选品决策

跨境电商和新消费品牌的选品团队都清楚一件事：真正的"下一个爆款"很少一上来就出现在电商平台的搜索热词榜上。一个新成分、一个新品类、一个新的使用场景，往往先在母婴、美妆、潮流类的垂类自媒体和公众号里被反复提起，等到搜索量和销量数据明显抬头时，早期窗口期已经过去，选品团队跟进的只是别人验证过的红利尾巴。

问题是，盯这批垂类公众号本身就是一份体力活。选品或买手每天要打开几十个账号，一篇篇翻看有没有提到新成分、新品类、新话题标签，把觉得有价值的信息手动摘录到 Excel 或者聊天记录里。账号数量少的时候还能坚持，一旦扩展到几十甚至上百个，翻阅频率就会不知不觉往后拖，今天漏看几个账号，明天漏看几个话题，一个趋势词到底是从什么时候开始被频繁提及、提及频率有没有明显上升，全凭个人印象，没有可回溯的记录支撑。

更麻烦的是，这些零散摘录很难沉淀成团队共享的历史数据。选品会议上有人说"这个成分最近很火"，却拿不出提及次数随时间变化的曲线，也说不清最早是哪篇文章提到的。决策更多依赖个人对信息的敏感度，而不是可以复盘、可以交接给新同事的量化依据。

## 问题的核心：趋势信号分散在无法批量抓取的公众号里

微信公众号没有官方的订阅或抓取接口，文章内容也无法被脚本直接拉取，这是趋势追踪自动化最前面卡住的一环。就算团队想写脚本统计"某个成分词在过去一个月的公众号提及次数变化"，第一步——把几十个账号的文章内容变成可编程读取的数据——就已经无法完成，只能退回到人工逐篇翻看、手动摘录的老办法，后面的关键词统计、趋势曲线、决策看板都无从谈起。

## 解决路径：把公众号内容转成可检索的结构化数据

[Mp2RSS](https://mp2rss.bugcode.dev) 把微信公众号文章转成结构化数据：贴入目标公众号任意一篇文章的链接（形如 `https://mp.weixin.qq.com/s?...`），即可订阅整个账号，此后该账号发布的每一篇新文章都会被持续收录，包含完整的 Markdown 正文，从发文到数据可见平均 2–3 小时。注册不需要微信账号，用 GitHub 或 Google 账号登录即可完成。

有了结构化的文章正文，趋势追踪就能拆成三个可编程的环节：定时拉取监测账号的增量文章，对文章正文做关键词命中与词频统计，再把统计结果沉淀成随时间变化的趋势记录，供选品会议直接调取，不再依赖任何人的记忆和主观印象。

## 落地步骤

### 第一步：梳理选品雷达要覆盖的垂类账号

先按品类圈定要监测的公众号清单：母婴、美妆个护、潮流穿搭等垂类自媒体号，以及关注新品发布、成分解读、消费趋势的行业媒体号。清单确定后逐个订阅，操作方式是贴入该账号任意一篇历史文章链接，具体流程参考[订阅管理指引](/guide/subscription)。账号数量多时，用 [CLI](/cli/) 批量订阅比逐个在网页操作快得多：

```bash
mp2rss auth login                              # 首次使用先登录
mp2rss mp subscribe https://mp.weixin.qq.com/s/xxxxxxxxxx
mp2rss mp subscribe https://mp.weixin.qq.com/s/yyyyyyyyyy
```

需要注意，首次订阅不会回溯该账号此前发布的历史文章，只从订阅时刻起持续收录新内容。这意味着趋势雷达需要一段积累期才能形成可信的对比基线——越早把要长期监测的垂类账号接入，后续趋势曲线的参考价值就越高。完整的鉴权和调用方式见[快速开始](/guide/quick-start)。

### 第二步：定时拉取文章正文，跑关键词与词频统计

趋势雷达要能"自动预警"，核心是拉取任务按固定周期运行，而不是等选品同事想起来才手动翻看。用 cron 或任意调度平台，按天触发一次拉取，通过 [Open API](/api/) 查询订阅账号的最新文章正文：

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles?pageSize=20" \
  -H "Authorization: Bearer {feed_key}"
```

返回数据按 `publishedAt` 倒序排列，每篇文章带 `title`、`publishedAt`、`contentMarkdown`（正文 Markdown 原文）等字段。拿到正文后，用一份预设的关键词表（成分名、品类词、话题标签）对全文做命中统计，逐日累计每个关键词的提及次数：

```python
import re
import requests
from collections import Counter

FEED_KEY = "your_feed_key"
HEADERS = {"Authorization": f"Bearer {FEED_KEY}"}
WATCH_WORDS = ["玻色因", "早C晚A", "预制菜", "多巴胺穿搭"]

def fetch_articles(mp_id):
    resp = requests.get(
        f"https://mp2rss.bugcode.dev/open-api/subscriptions/{mp_id}/articles",
        params={"pageSize": 20},
        headers=HEADERS,
    )
    return resp.json()["items"]

def count_mentions(articles):
    hits = Counter()
    for a in articles:
        text = a.get("contentMarkdown") or ""
        for word in WATCH_WORDS:
            hits[word] += len(re.findall(word, text))
    return hits
```

每天跑一次，把当天的命中次数追加写入数据库或表格，几周之后就能看到每个关键词的提及频率曲线——是持续走高，还是昙花一现，一目了然，不再需要凭印象判断。

### 第三步：沉淀选品线索库，让趋势可回溯、可复盘

统计结果之外，更重要的是保留原始出处。把命中关键词的文章标题、发布时间、原文链接一并存入线索库，选品会议上提到某个趋势词，随时可以点开对应文章核实上下文，而不是只有一句"最近好像很火"。用 [CLI](/cli/commands) 也可以按需导出订阅账号的文章列表用于批量核对：

```bash
mp2rss mp list -o json | jq -r '.items[] | "\(.mpId)\t\(.mpName)"'
```

线索库积累到一定周期后，团队复盘某一季度选对或选错的品类时，也能回头查证：这个品类最早是从哪篇文章、哪个账号开始被提及的，提前跟进的窗口期原本有多长，为下一轮选品决策提供参照。

## 效果对比

| 维度 | 人工刷号选品 | 结构化数据 + 关键词统计 |
| ---- | ---- | ---- |
| 覆盖账号数 | 受精力限制，扩展成本高 | 可批量订阅，扩展只需加一行订阅 |
| 趋势判断依据 | 个人印象与主观敏感度 | 提及频率曲线，可量化对比 |
| 历史可追溯性 | 零散记在聊天记录或表格里 | 原文与时间线一并沉淀，随时核对 |
| 团队协作与交接 | 依赖个人经验，难以交接 | 线索库可共享，新同事可直接查阅 |

## 常见问题

**新订阅的公众号能看到之前发布的历史文章吗？**
不能。首次订阅只从订阅时刻起持续收录新发布的文章，不会回溯历史内容。因此趋势雷达的对比基线需要一段积累期，建议尽早把要长期监测的垂类账号接入。

**从公众号发文到能查询到数据，一般要等多久？**
平均 2–3 小时。按天触发一次拉取任务，通常已经能覆盖前一天发布的全部新文章，不影响趋势统计的时效性。

**除了微信公众号，还能同时监测其他平台的账号吗？**
支持同时订阅 X（Twitter）账号，同样以结构化数据交付，可以和公众号数据合并进同一套关键词统计和线索库流程。

**关键词统计需要自己写代码实现吗？**
Mp2RSS 提供 [Open API](/api/) 和 [CLI](/cli/) 输出标准化的结构化数据（含文章正文），关键词命中统计、趋势曲线计算属于在此基础上按团队需求编写的轻量脚本，逻辑可以按上文示例扩展。

**监测账号数量有上限吗？**
按套餐档位区分：49 元/月支持 50 个订阅、99 元/月支持 100 个、399 元/月支持 400 个，各档位功能一致，仅订阅数量上限不同，详见[会员与计费](/guide/membership)。
