# 公众号更新自动化：用 n8n / Zapier 搭建新文章分发工作流

做运营自动化或个人效率工具搭建的人，常年绕不开一个矛盾：想关注的公众号——可能是行业媒体、竞品官方号、上下游合作方的号——更新频率不固定，几天发一篇也可能一天发好几篇，靠人工打开微信逐个刷新，要么错过时机，要么被大量无关推送淹没。微信本身也不提供"新文章即时通知到第三方系统"的能力，服务号消息还会被折叠进"订阅号"文件夹，团队协作场景里根本没法把这条信息流接入群通知或表格记录。

更麻烦的是，很多人已经习惯用 n8n、Zapier 这类工具把日常信息流自动化——邮件到表格、表单到群消息、日历到待办——公众号却始终是这条自动化流水线里补不上的一环，原因很简单：n8n 和 Zapier 的原生触发器大多依赖 RSS / Webhook / 标准 API，而公众号既没有官方 RSS 输出，也没有开放 Webhook，想把"某公众号发新文章"做成一个自动化触发事件，只能退回到自己写爬虫定时抓取、解析页面、判重去重，这一整套维护成本对个人开发者和小团队来说并不轻。

问题的关键不是 n8n 或 Zapier 不够用，而是公众号这一端一直缺一个标准化的、可以直接喂给自动化工具的数据接口。

## 解决思路：把公众号变成 RSS 触发源

[Mp2RSS](https://mp2rss.bugcode.dev) 把公众号内容转换成标准格式的 Feed：贴入任意一篇公众号文章的链接（形如 `https://mp.weixin.qq.com/s?...`），即可订阅该文章所属的整个公众号，此后该号新发布的文章会被持续收录，从发文到数据可见平均 **2–3 小时**。登录使用 GitHub / Google 账号，账户会生成 Feed 密钥，对应的 Feed 链接同时提供 **RSS 2.0 / Atom 1.0 / JSON Feed 1.1** 三种格式，这些正是 n8n 的 RSS Feed Trigger 节点和 Zapier 的 "RSS by Zapier" 触发器原生支持的输入源，不需要额外写解析代码。

## 落地步骤

### 第一步：订阅公众号并拿到 Feed 链接

先按[订阅管理指引](/guide/subscription)贴入目标公众号任意一篇文章链接完成订阅，登录后在账户设置里能看到对应的 Feed 链接，具体操作可参考[快速开始](/guide/quick-start)。需要提醒的是，首次订阅不会回溯历史文章，只从订阅时刻起收录该号后续发布的新文章，建议先选一个近期更新频率较高的号做联调测试，避免刚接入时长时间看不到新数据。

### 第二步：在 n8n 中配置 RSS 触发器

在 n8n 里新建工作流，添加 **RSS Feed Trigger** 节点，把上一步拿到的 Feed 链接填进去，设置轮询间隔（比如每 15 或 30 分钟检查一次）。节点触发后会拿到新文章的标题、链接、摘要等字段，后面可以接：

- **IF 节点**：按标题关键词过滤，只对包含特定词（如竞品名、产品名）的文章继续往下走；
- **Slack / 飞书 / 企业微信节点**：把命中的文章标题和链接推到指定群；
- **Notion / Google Sheets 节点**：把每篇新文章写成一条记录，自动积累成一份更新日志。

如果需要文章的完整正文而不只是摘要，可以在 RSS 触发之后加一个 **HTTP Request** 节点，调用 Open API 按 `mpId` 拉取文章详情，取 `contentMarkdown` 字段：

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

完整字段说明见 [Open API 文档](/api/)。这一步适合需要把正文直接送进摘要模型或存档系统的场景，不想接 HTTP Request 节点的话，也可以用命令行工具 `mp2rss` 在服务器端定时任务里做同样的事，用法见 [CLI 文档](/cli/)。

### 第三步：Zapier 上的等价配置

不用 n8n 的话，Zapier 里对应用 **"RSS by Zapier"** 这个内置 App，选择触发器 **"New Item in Feed"**，同样填入 Feed 链接，Zapier 会按设定频率轮询。后面接 Action 时可以直接选 Slack、Notion、Google Sheets 等常见目标应用，不需要额外配置认证，因为 Feed 链接本身已经携带访问凭据，读取不需要再单独登录。

### 第四步：按监测目的拆分工作流

Feed 链接默认按账户合并该账户下所有公众号（以及订阅的 X 账号）的更新时间线。如果只想针对某一个特定公众号触发通知，可以在触发器后接一个过滤节点按标题或来源关键词二次筛选；如果监测目的差异较大（比如一路是竞品追踪、一路是行业资讯摘要），也可以考虑用不同账户分别管理订阅清单和 Feed 密钥，让每条自动化工作流对应一个更干净的数据源，避免所有通知挤在同一个群里失去信噪比。

## 常见问题

**公众号本身没有 RSS，为什么能直接用 RSS 触发器？**
Mp2RSS 把公众号内容转换成标准的 RSS 2.0 / Atom 1.0 / JSON Feed 1.1 格式的 Feed 链接，n8n 的 RSS Feed Trigger 节点和 Zapier 的 "RSS by Zapier" 触发器都可以直接读取这类标准格式，不需要额外解析公众号页面。

**新文章发布后，自动化多久能收到通知？**
从发文到 Mp2RSS 数据可见平均 2–3 小时，再叠加 n8n 或 Zapier 本身设置的轮询间隔（通常几分钟到半小时一次），实际收到通知的时间是两者叠加的结果，可以按需要调整轮询频率。

**一个 Feed 链接订阅了多个公众号，能只对某一个号触发通知吗？**
Feed 链接默认合并账户下全部公众号与 X 账号的更新时间线，可以在 n8n 或 Zapier 的过滤节点里按标题、来源关键词二次筛选，监测目的差异较大时也可以用不同账户分别管理订阅清单。

**接入后能马上看到这个号过去发过的文章吗？**
不能。首次订阅不回溯历史文章，只从订阅时刻起持续收录该号后续发布的新文章，联调自动化工作流时建议先选一个近期更新较频繁的号做测试。

**除了公众号，还能作为同一套自动化的触发源吗？**
支持订阅 X（Twitter）账号，交付形态与公众号一致，可以合并进同一个 Feed 链接，用同一套 n8n 或 Zapier 工作流处理，不需要为不同信源单独搭建流程。
