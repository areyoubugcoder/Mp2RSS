# 猎头顾问如何监测目标公司公众号：从组织变动挖掘寻访线索

做中高端寻访的猎头顾问都清楚,候选人和职位机会的线索很少直接写在招聘网站上。一家公司要不要扩张某个业务线、有没有新设立的事业部、核心高管有没有变动、组织架构是不是刚做过调整——这些信息往往先出现在公司自己的微信公众号里:一条新业务线上线的内部通稿、一场事业部成立仪式的报道、一篇高管履新的介绍文章。等到职位真正挂到招聘网站上,往往已经是内部流程走完之后的事,留给顾问的反应时间很短。

现实中,这类信号的获取方式基本还停留在人工阶段:顾问在几十个客户公司和潜在客户公司的公众号之间来回切换,逐篇点开看有没有值得关注的内容,再手动记进 Excel 或笔记软件。这套流程有几个明显的短板。一是**发现滞后**,公众号不会主动推送提醒,顾问只能凭习惯定期去翻,一条关键信号可能要等几天甚至几周才被看到,等注意到时候选人可能已经被别的猎头联系过。二是**难以规模化**,同时盯几十上百家客户和目标公司的公众号,靠人工点开阅读的方式很快就会力不从心,只能优先盯最重要的几家,其余的基本处于失联状态。三是**信息没有沉淀**,某家公司半年前发过一次组织调整的通稿,现在想回溯查证,往往只能凭记忆或翻聊天记录,没有一份可以直接搜索的历史素材库。

这几个短板的共同原因是:目标公司公众号的内容始终只是一篇篇独立的网页文章,没有被转成可以批量处理、持续追踪、可检索的结构化数据。只要这一步没解决,寻访线索的挖掘就只能停留在"顾问凭经验刷公众号"的阶段。

## 解决思路:把目标公司公众号变成结构化寻访情报流

[Mp2RSS](https://mp2rss.bugcode.dev) 把公众号内容转成可编程的数据源:把目标公司任意一篇公众号文章的链接(形如 `https://mp.weixin.qq.com/s?...`)贴入控制台,即可订阅该文章所属的整个公众号,此后该号发布的每篇新文章都会持续被收录,正文以 **Markdown** 结构化形式交付,从发文到数据可见平均 **2–3 小时**。登录只需要 GitHub 或 Google 账号,不涉及顾问本人或客户的微信账号,适合团队共用一个订阅清单。

对猎头团队来说,这意味着寻访情报可以拆成两层:**采集层交给系统**——批量订阅需要长期跟踪的客户公司、潜在客户公司、候选人所在公司的官方号;**判断层留给顾问**——顾问只在系统提示出现关键信号或例行梳理候选池时介入,不需要每天花时间挨个刷公众号找线索。

## 落地步骤

### 第一步:梳理目标公司清单并批量订阅

先列出需要长期覆盖的公司范围,通常包括:现有客户公司(方便及时发现新的岗位需求信号)、重点潜在客户(还没建立合作但有开发价值)、候选人当前所在的公司(便于观察组织变动带来的跳槽窗口)。找到每家公司任意一篇公众号文章的链接贴入即可完成订阅,不需要知道公众号的内部识别信息,具体操作参考[订阅管理指引](/guide/subscription)。

如果要覆盖的公司数量较多,批量订阅可以用 [Open API](/api/) 脚本化完成:

```bash
curl -X POST "https://mp2rss.bugcode.dev/open-api/subscriptions" \
  -H "Authorization: Bearer {feed_key}" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://mp.weixin.qq.com/s?__biz=..."}'
```

需要提醒的是,首次订阅不会回溯历史文章,只从订阅时刻起收录该号之后发布的新文章。因此对于已经列入寻访计划的重点公司,越早完成订阅越好,避免错过订阅前的组织变动信号。

### 第二步:按信号类型筛选新文章

寻访顾问真正关心的不是"这家公司发了一篇文章",而是这篇文章有没有透露值得跟进的线索。定时调用文章列表接口拉取增量文章,正文以 Markdown 字段返回,可以直接跑关键词规则或送入 LLM 做初筛:

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

对猎头场景常用的筛选维度包括:新业务线或事业部成立、高管履新与人事任命、组织架构调整通稿、新办公地点或分支机构设立、融资与规模扩张相关表述——这些内容背后往往对应着新岗位需求或候选人变动窗口。正文已经是干净的 Markdown、不含页面样式和广告噪声,不论是写关键词规则脚本,还是直接把全文喂给 LLM 做摘要和信号打标,都能省掉一轮网页解析和清洗的工作量。不想写代码的顾问,也可以先用命令行工具 `mp2rss` 把文章拉到本地做初步浏览,安装与使用方式见 [CLI 文档](/cli/)。

### 第三步:沉淀为可检索的寻访素材库

筛选出的信号按公司、按信号类型、按时间线归档,就形成了一份可以直接检索的寻访情报库——不再依赖顾问个人的记忆或某份零散的 Excel。跟进某个候选人或某家客户时,可以直接按公司名筛选,回看近半年到一年内发生过的组织变动,判断当前是不是合适的接触时机。这份素材库也是团队内部交接候选人和客户资源时最直接的参考,不需要老顾问口头转述历史背景。

## 人工刷号与结构化信号流对比

| 维度 | 人工刷目标公司公众号 | 结构化信号流 |
| ---- | ---- | ---- |
| 覆盖范围 | 精力有限,通常只能盯少数重点公司 | 可批量订阅,覆盖客户、潜在客户与候选人所在公司 |
| 发现时延 | 数天到数周,依赖主动翻阅 | 平均 2–3 小时 |
| 信息沉淀 | 分散在个人笔记与聊天记录 | 结构化 Markdown 正文,统一可检索 |
| 团队交接 | 依赖老顾问口头转述 | 按公司与信号类型直接筛选时间线 |

## 常见问题

**需要用猎头顾问自己或客户公司的微信账号才能订阅吗?**
不需要。Mp2RSS 使用 GitHub / Google 账号登录,订阅动作只需要一篇目标公司公众号的文章链接,全程不涉及微信账号。

**订阅之后能看到这家公司过去发过的历史文章吗?**
不能。首次订阅不回溯历史文章,只从订阅时刻起持续收录该号之后发布的新文章,建议对已经确定要长期跟踪的客户和候选人所在公司尽早完成订阅。

**从目标公司发文到顾问能查到,大概要等多久?**
平均 2–3 小时。对大多数寻访跟进场景来说,这个时延足以支撑顾问在信号出现后的当天就判断是否需要主动接触。

**一个团队账号能同时订阅多少家公司的公众号?**
按套餐档位区分:49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个,功能权益一致仅订阅上限不同,具体见[会员与计费](/guide/membership)。同时跟踪客户公司、潜在客户与候选人所在公司时,可以按需要覆盖的数量选择合适档位。

**候选人所在公司只在其他平台活跃,不怎么发公众号怎么办?**
Mp2RSS 同时支持订阅 X(Twitter)账号,交付形态与公众号一致,可以并入同一套信号采集与归档管道,不需要为不同信源分别维护独立流程。
