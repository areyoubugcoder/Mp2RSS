# 教育培训机构竞品情报团队如何监测同行公众号：新课上线与价格调整追踪法

在教育培训机构做市场情报、产品规划或招生运营的人员，经常要回答类似的问题：某个竞品机构这个月新开了哪些班型？寒暑假班的价格相比去年同期涨了还是降了？限时早鸟优惠什么时候截止，续报政策有没有变化？这些信息很少第一时间出现在竞品机构的官网上，反而经常先由其微信公众号发布——一篇新课上线通稿、一篇寒假班价格政策、一篇校区续报活动推文，往往就是同行招生节奏和定价策略调整的最早信号。

问题是，这类信息目前大多依赖人工盯守。市场情报或产品规划岗位的同事需要在几十个竞品机构官方号、校区分号、行业媒体号之间来回切换，逐篇打开、逐篇摘录关键信息，再整理进内部价格监测表或周报。这套流程有两个明显的短板。第一是**发现滞后**：公众号没有订阅提醒机制，除非每天主动翻阅，否则一次区域校区的限时降价可能过去几天才被注意到，而招生季的定价决策往往需要在竞品调价的当天或次日就拿出跟进方案，滞后几天基本就错过了当季的招生窗口。第二是**缺少结构化沉淀**：某个竞品课程体系过去几个学期的价格变动、班型调整、优惠节奏散落在不同人的截图和聊天记录里，新同事接手时很难快速理清某条产品线的定价走势，学期复盘时也只能凭记忆拼凑时间线。

这两个短板的根源相同：竞品机构公众号的内容始终只以网页文章的形式存在，没有转成结构化、可检索、可编程处理的数据。只要这一步没有解决，情报团队就只能靠人眼和记性去追踪课程与价格节奏。

## 解决思路：把竞品机构公众号变成结构化数据源

[Mp2RSS](https://mp2rss.bugcode.dev) 把公众号内容处理成可编程的数据源：贴入竞品机构公众号任意一篇文章的链接（形如 `https://mp.weixin.qq.com/s?...`），即可订阅该文章所属的整个公众号；此后该号发布的每篇新文章都会被持续收录，正文以 **Markdown** 结构化形式交付，从发文到数据可见平均 **2–3 小时**。登录使用 GitHub / Google 账号，不涉及企业或个人微信账号，适合情报团队用统一账号管理需要覆盖的竞品信源清单。

对教育培训行业情报团队来说，这意味着追踪工作可以拆成两层：**采集层交给系统**——批量订阅需要覆盖的竞品机构官方号、重点校区分号、行业媒体号，新文章自动进入数据流；**研判层留给人**——产品规划或定价策略同事只在关键信号出现或例行复盘时介入解读，不再花时间做重复的翻找和摘录。

## 落地步骤

### 第一步：梳理竞品信源并批量订阅

先确定需要覆盖的公众号范围，通常包括：竞品机构的总部官方号、重点竞争区域的校区分号（区域性优惠和早鸟价往往先由校区号发布）、以及覆盖该细分赛道（K12、素质教育、职业培训等）的教育行业媒体号。找到每个号任意一篇文章的链接贴入 Mp2RSS 控制台即可完成订阅，具体操作参考[订阅管理指引](/guide/subscription)。

需要覆盖的号数量较多时，批量订阅可以用 [Open API](/api/) 脚本化完成：

```bash
curl -X POST "https://mp2rss.bugcode.dev/open-api/subscriptions" \
  -H "Authorization: Bearer {feed_key}" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://mp.weixin.qq.com/s?__biz=..."}'
```

需要提醒的是，首次订阅不会回溯历史文章，只从订阅时刻起收录该号后续发布的新文章。因此建立某个竞品课程体系的价格追踪项目时，越早完成订阅越好，避免错过订阅前的历史价格与班型变动记录。

### 第二步：按信号类型抓取与分类

情报团队真正需要的不是“竞品发了一篇文章”这个事实，而是这篇文章属于哪一类信号。定时调用文章列表接口拉取增量文章，正文以 Markdown 字段返回，可以直接跑关键词规则或送入 LLM 做分类：

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

常见的分类维度包括：新课程与新班型上线、正价课与体验课定价调整、寒暑假班早鸟优惠与截止时间、续报与转介绍政策变化、校区扩张与师资公告。因为正文已经是干净的 Markdown、不含页面样式与广告位噪声，无论是写关键词匹配脚本按班型名称和“开班”“优惠”“涨价”等关键词过滤，还是直接把全文喂给 LLM 做摘要与分类，都可以省掉一轮网页解析和清洗的工作量。不想写代码的团队，也可以先用命令行工具 `mp2rss` 把文章拉到本地做初步筛选，安装与使用方式见 [CLI 文档](/cli/)。

### 第三步：沉淀为可检索的课程价格追踪库

分类后的文章按竞品机构、按课程体系、按信号类型归档，就形成了一份可以直接检索的竞品课程与价格追踪库——不再依赖某位同事的记忆或聊天记录里的截图。学期复盘时可以直接按课程体系筛选，回看过去几个学期内该产品线从开班公告到历次早鸟优惠、续报政策调整的完整时间线，判断本方招生节奏和定价策略是应该跟进还是观望。这份追踪库同时也是新同事接手某条细分赛道竞品档案时最快的上手材料。

## 常见问题

**需要绑定竞品机构的公众号或自己的企业微信账号吗？**
不需要。Mp2RSS 使用 GitHub / Google 账号登录，订阅动作只需要一篇目标公众号的文章链接，全程不涉及微信账号。

**订阅之后能看到竞品机构过去发过的历史课程和价格文章吗？**
不能。首次订阅不回溯历史文章，只从订阅时刻起持续收录该号后续发布的新文章，建议追踪某个竞品课程体系时尽早完成订阅，避免错过订阅前的历史价格与班型变动记录。

**从竞品机构发文到我方能查到，大概要等多久？**
平均 2–3 小时。对多数招生季跟进决策和例行复盘场景来说，这个时延足以支撑情报团队在信号出现后的当天就介入研判。

**一个团队账号能同时订阅多少个竞品相关的号？**
按套餐档位区分：49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个，功能权益一致仅订阅上限不同，具体见[会员与计费](/guide/membership)。覆盖多家竞品机构总部号与多个重点校区分号时，可以按需要覆盖的信源数量选择合适档位。

**除了公众号，还能跟踪竞品机构在其他平台的动态吗？**
支持订阅 X（Twitter）账号，交付形态与公众号一致，可以并入同一套信号采集与归档管道，不需要为不同信源分别维护单独的流程。
