# 餐饮连锁品牌拓店团队如何监测同行公众号：新店开业与菜单调价追踪法

在餐饮连锁品牌做拓店选址、区域运营或产品定价的人员，经常要回答类似的问题：某个同行连锁品牌这个月在哪些城市又开了几家新店？主打的商圈类型是购物中心还是社区底商？招牌套餐或爆款单品最近有没有调价，新品上新节奏是不是在加快？这些信息很少第一时间出现在同行品牌的官网或招商平台上，反而经常先由其微信公众号发布——一篇新店开业预告、一篇城市加密战报、一篇季节限定菜单推文，往往就是同行拓店节奏和定价策略调整的最早信号。

问题是，这类信息目前大多依赖人工盯守。拓店或产品运营岗位的同事需要在几十个同行品牌官方号、区域分号、餐饮行业媒体号之间来回切换，逐篇打开、逐篇摘录关键信息，再整理进内部选址对比表或调价台账。这套流程有两个明显的短板。第一是**发现滞后**：公众号没有订阅提醒机制，除非每天主动翻阅，否则一次区域品牌的新店开业或套餐降价可能过去几天才被注意到，而拓店决策和价格跟进往往需要在同行动作公开后的当天或次日就拿出应对方案，滞后几天基本就错过了同商圈的占位窗口。第二是**缺少结构化沉淀**：某个同行品牌过去几个季度的开店城市、商圈类型、菜单调价节奏散落在不同人的截图和聊天记录里，新同事接手某个区域的竞品档案时很难快速理清拓店走势，季度复盘时也只能凭记忆拼凑时间线。

这两个短板的根源相同：同行连锁品牌公众号的内容始终只以网页文章的形式存在，没有转成结构化、可检索、可编程处理的数据。只要这一步没有解决，拓店与产品运营团队就只能靠人眼和记性去追踪开店与定价节奏。

## 解决思路：把同行连锁品牌公众号变成结构化数据源

[Mp2RSS](https://mp2rss.bugcode.dev) 把公众号内容处理成可编程的数据源：贴入同行连锁品牌公众号任意一篇文章的链接（形如 `https://mp.weixin.qq.com/s?...`），即可订阅该文章所属的整个公众号；此后该号发布的每篇新文章都会被持续收录，正文以 **Markdown** 结构化形式交付，从发文到数据可见平均 **2–3 小时**。登录使用 GitHub / Google 账号，不涉及企业或个人微信账号，适合拓店与产品团队用统一账号管理需要覆盖的同行品牌信源清单。

对餐饮连锁品牌来说，这意味着追踪工作可以拆成两层：**采集层交给系统**——批量订阅需要覆盖的同行品牌总部官方号、重点区域分号、餐饮行业媒体号，新文章自动进入数据流；**研判层留给人**——拓店或产品定价同事只在关键信号出现或例行复盘时介入解读，不再花时间做重复的翻找和摘录。

## 落地步骤

### 第一步：梳理同行信源并批量订阅

先确定需要覆盖的公众号范围，通常包括：同行连锁品牌的总部官方号、重点竞争城市的区域分号（新店开业和区域性优惠往往先由区域号发布）、以及覆盖该细分赛道（火锅、茶饮、快餐等）的餐饮行业媒体号。找到每个号任意一篇文章的链接贴入 Mp2RSS 控制台即可完成订阅，具体操作参考[订阅管理指引](/guide/subscription)。

需要覆盖的号数量较多时，批量订阅可以用 [Open API](/api/) 脚本化完成：

```bash
curl -X POST "https://mp2rss.bugcode.dev/open-api/subscriptions" \
  -H "Authorization: Bearer {feed_key}" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://mp.weixin.qq.com/s?__biz=..."}'
```

需要提醒的是，首次订阅不会回溯历史文章，只从订阅时刻起收录该号后续发布的新文章。因此建立某个同行品牌的拓店与调价追踪项目时，越早完成订阅越好，避免错过订阅前的历史开店与价格变动记录。

### 第二步：按信号类型抓取与分类

拓店团队真正需要的不是“同行发了一篇文章”这个事实，而是这篇文章属于哪一类信号。定时调用文章列表接口拉取增量文章，正文以 Markdown 字段返回，可以直接跑关键词规则或送入 LLM 做分类：

```bash
curl "https://mp2rss.bugcode.dev/open-api/subscriptions/{mpId}/articles" \
  -H "Authorization: Bearer {feed_key}"
```

常见的分类维度包括：新店开业与城市加密公告、商圈类型与选址偏好（购物中心、社区底商、写字楼）、招牌套餐与单品调价、季节限定与联名新品上新、加盟招商政策变化。因为正文已经是干净的 Markdown、不含页面样式与广告位噪声，无论是写关键词匹配脚本按城市名、商圈类型和“开业”“上新”“调价”等关键词过滤，还是直接把全文喂给 LLM 做摘要与分类，都可以省掉一轮网页解析和清洗的工作量。不想写代码的团队，也可以先用命令行工具 `mp2rss` 把文章拉到本地做初步筛选，安装与使用方式见 [CLI 文档](/cli/)。

### 第三步：沉淀为可检索的拓店与菜单价格追踪库

分类后的文章按同行品牌、按城市、按信号类型归档，就形成了一份可以直接检索的拓店节奏与菜单价格追踪库——不再依赖某位同事的记忆或聊天记录里的截图。季度复盘时可以直接按城市或品牌筛选，回看过去几个季度内某个同行品牌从开店公告到历次套餐调价、新品上新的完整时间线，判断本方区域拓店节奏和定价策略是应该跟进还是观望。这份追踪库同时也是新同事接手某个区域竞品档案时最快的上手材料。

## 常见问题

**需要绑定同行品牌的公众号或自己的企业微信账号吗？**
不需要。Mp2RSS 使用 GitHub / Google 账号登录，订阅动作只需要一篇目标公众号的文章链接，全程不涉及微信账号。

**订阅之后能看到同行品牌过去发过的历史开店和调价文章吗？**
不能。首次订阅不回溯历史文章，只从订阅时刻起持续收录该号后续发布的新文章，建议追踪某个同行品牌时尽早完成订阅，避免错过订阅前的历史开店与价格变动记录。

**从同行品牌发文到我方能查到，大概要等多久？**
平均 2–3 小时。对多数拓店跟进决策和季度复盘场景来说，这个时延足以支撑团队在信号出现后的当天就介入研判。

**一个团队账号能同时订阅多少个同行相关的号？**
按套餐档位区分：49 元/月 50 个订阅、99 元/月 100 个、399 元/月 400 个，功能权益一致仅订阅上限不同，具体见[会员与计费](/guide/membership)。覆盖多家同行品牌总部号与多个重点城市区域号时，可以按需要覆盖的信源数量选择合适档位。

**除了公众号，还能跟踪同行品牌在其他平台的动态吗？**
支持订阅 X（Twitter）账号，交付形态与公众号一致，可以并入同一套信号采集与归档管道，不需要为不同信源分别维护单独的流程。
