# Agent 与 CLI 第一次获取公众号和 X 内容

先完成一个能够检查结果的小任务：从一个已订阅的信息源取到一条有效内容，并能打开对应的原文链接。安装成功、授权成功或订阅成功，都不等于已经拿到内容。

最后核对：2026-11-02。下面的命令与现有 CLI、Open API 契约一致；示例 ID 和文章链接需要换成自己的数据。

## 开始前确认三件事

1. 已有 [Mp2RSS 账户](https://mp2rss.bugcode.dev)，并具有有效会员或站内显示的试用资格。注册不保证赠送试用，价格和开通规则见 [会员与计费](/guide/membership)。
2. 准备一个要跟踪的信息源。公众号可使用文章链接建立订阅；X 账号先在 Web 控制台订阅，CLI 不提供 X 搜索、订阅或取消订阅操作。
3. 接受内容可见时间取决于来源发布与采集进度。新建订阅不保证立即有内容，也不保证提供完整历史文章。

## 1. 安装并核对命令

已有 Node.js 与 pnpm 的环境可执行：

```bash
pnpm add -g @mp2rss/cli
mp2rss --version
mp2rss --help
```

如果终端找不到 `mp2rss`，先检查 pnpm 全局可执行目录是否在 `PATH` 中；其他平台和安装方式见 [安装](/cli/install)。不要通过反复注册账户解决本地安装问题。

使用 Agent Skill 时，CLI 需支持 `skills` 命令（v1.2.0 起提供）。先检查帮助，再同步：

```bash
mp2rss skills --help
mp2rss skills sync --global
mp2rss skills status
```

同步后确认当前 Agent 能发现这些 Skill；仅同步成功并不表示任意 Agent 客户端已经加载。也可以先直接在终端完成下面的读取，再处理 Agent 的 Skill 加载问题。各客户端接入方式见 [Agent 接入页](https://mp2rss.bugcode.dev/agents)。

## 2. 在浏览器授权

```bash
mp2rss auth login
mp2rss auth status
```

按浏览器提示登录并授权，回到终端查看状态。远程机器、无浏览器环境或重新授权请参照 [登录](/cli/login)。Feed 密钥与包含它的链接只供自己或受信工具使用，不要放进公开文章、截图或问题反馈。

授权后仍需通过一次实际读取确认服务可用；本地显示已保存凭据不代表会员在期或目标源已有内容。

## 3. 公众号：先取真实 ID，再读正文

先列出当前账户的订阅：

```bash
mp2rss mp list -o json
```

从返回的 `items` 中找到目标公众号的 `mpId`。没有订阅时，可用一篇真实文章的完整链接发起订阅，URL 应加引号，避免其中的 `&` 被 shell 当作控制符：

```bash
mp2rss mp subscribe 'https://mp.weixin.qq.com/s/替换为真实文章链接'
mp2rss mp list -o json
```

将下面的 `2234567` 换成上一步得到的 `mpId`：

```bash
mp2rss mp articles 2234567 --page-size 5 -o json
```

检查返回结果，而不是只看退出码：

| 要检查的字段 | 什么结果可以继续使用 |
| --- | --- |
| `items` | 至少有一条目标源的文章；空数组表示本次没有可用文章 |
| `title`、`originalUrl` | 标题与原文来源能够对应 |
| `publishedAt` | 明确文章实际发布时间，不能把拉取时间当作发文时间 |
| `contentMarkdown` | 非空时才用作正文输入；可能为 `null`，此时不能让模型编造正文 |

需要阅读全文的任务，应确认正文非空后再交给 Agent。只取到标题或摘要时，输出中说明缺少正文，并保留原文链接。分页与完整字段见 [命令参考](/cli/commands#mp-articles)。

## 4. X：先在 Web 订阅，再获取推文或长文

在控制台「订阅管理 → X」完成订阅，然后运行：

```bash
mp2rss x list -o json
```

从返回项中复制 `xUserId`，不要用 `@用户名` 代替。下面的数字仅为示例：

```bash
mp2rss x posts 44196397 -o json
mp2rss x articles 44196397 -o json
```

推文检查 `content`、`postId` 与 `postedAt`；接口没有直接返回推文 URL，可用账号用户名与 `postId` 组成 `https://x.com/用户名/status/推文ID`，再打开核对。长文检查 `contentMarkdown`、`url` 与 `publishedAt`。两类内容分别返回，推文列表非空并不表示长文列表也应有数据。详细字段见 [X 命令参考](/cli/commands#x)。

## 5. 给 Agent 一条能验收的任务

可以使用下面的任务描述，把信息源名称换成自己已订阅的源：

> 列出我已订阅的信息源，找到指定源并读取最近可用内容。只总结确实返回且正文非空的内容，每条附原文链接与发布时间。没有内容、正文为空或调用失败时说明实际情况，不要补写来源没有提供的事实，不要输出 Feed 密钥。

完成后抽查一条回答：来源是否正确，时间是否正确，总结是否能在返回正文中找到依据。若需要保存输入输出，只保存获准使用的内容，不要连同凭据一起分享。

## 没拿到内容时怎么排查

| 现象 | 下一步 |
| --- | --- |
| 本地提示没有该命令 | 核对 `mp2rss --version` 与帮助；按安装页更新 CLI |
| 返回 401 或密钥失效 | 按登录页重新授权，确认使用的是正确账户的凭据 |
| 返回 403、会员未开通或已到期 | 到控制台核对会员状态与开通结果；重复安装 CLI 无法解决 |
| 订阅列表为空 | 确认账户、订阅是否成功，以及 MP / X 是否选对；X 在 Web 管理 |
| `items` 为空 | 检查信息源是否已有可见内容、新订阅是否仍在等待更新；暂不做正文总结 |
| 有文章但正文为空 | 说明正文缺失，保留来源链接；不要将空正文记为完整内容获取成功 |
| 接口或上游报错 | 保留不含密钥的错误信息和时间，参照 [FAQ](/cli/faq) 排查 |

## 常见问题

**可以不打开浏览器，直接让 CLI 订阅 X 吗？**

目前不可以。X 的搜索与订阅管理在 Web 控制台，CLI 读取已订阅账号的推文和长文。

**刚订阅就没有文章，是不是配置失败？**

不一定。先确认订阅存在，再检查内容是否已经可见。新订阅不保证立即返回文章，更不能据此承诺完整历史覆盖。

**返回一条会员到期通知，算成功获取内容吗？**

不算。应取得目标信息源的真实内容；需要正文的任务还要核对正文非空。通知条目只用于提示服务状态。

**能否把一次成功读取当作长期工作流已完成？**

不能。之后还需验证分页、增量去重、失败处理和会员状态。先完成本文的首次读取，再按 [Open API 文档](/api/) 与自己的任务需求设计同步流程。
