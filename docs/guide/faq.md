# 常见问题

## 账户与登录

### 我可以不授权邮箱访问直接登录吗？

不可以。Mp2RSS 以邮箱作为账户唯一标识，OAuth 回调必须返回可用邮箱，否则登录会被拒绝。请先在 OAuth 提供方处把邮箱设为公开或完成邮箱验证后再重试。

### 我先后用 GitHub 和 Google 登录，会被建成两个账户吗？

不会。只要两次登录返回的是同一个邮箱，就会落到**同一个账户**，订阅和会员权益互通。

## 信息源与订阅

### Mp2RSS 现在支持哪些信息源？

当前支持 **微信公众号（MP）** 与 **X（Twitter）账号** 两类信息源；订阅、Feed 输出、API、CLI 都把两类源对齐为同一套语义。

### 单个账户最多能订阅多少个信息源？

**400 个**，公众号与 X 账号**合并计算**。

### 取消订阅后再订阅会浪费配额吗？

不会。24 小时内重新订阅同一信息源（无论 MP 还是 X），不占用新的订阅配额。

### 我能从某篇公众号文章直接反查并订阅吗？

可以。在「添加订阅」里贴入任意一篇公众号文章的 URL，系统会通过反查识别其来源公众号并完成订阅。

### 为什么我刚订阅一个公众号 / X 账号，列表里显示「暂无内容」？

这是预期行为。**首次订阅时不会回溯历史内容**，Mp2RSS 只从订阅成功那一刻起，把信息源后续新发布的内容纳入抓取范围。所以新订阅的公众号 / X 账号会先经历一段「空窗期」——直到该账号发出第一条新内容，订阅列表与 Feed 才会开始有条目。

## X（Twitter）信息源

### X 和公众号订阅有什么区别？

订阅 / 取消订阅 / Feed 输出的体验是一致的，但有两处差异：

1. **业务键不同**：公众号用 `mpId`（整数），X 用 `xUserId`（字符串数字串）；
2. **内容形态不同**：公众号只有「文章」一种形态；X 同时有「推文 (`posts`)」与「长文 (`articles`)」两种形态，Open API 各有对应端点，Feed 公开层也分 `/x-posts/` 与 `/x-articles/` 两个 path。

订阅配额、Feed 密钥共用同一套规则。

### 为什么订阅 X 要使用 `xUserId` 而不是 `@handle`？怎么拿到 `xUserId`？

X 的 `@handle`（username）允许用户随时修改，但 `xUserId` 是 X 内部的不可变 user_id，所以 Mp2RSS 以 `xUserId` 为业务键。拿到 `xUserId` 的方式：

- **控制台搜索**：在「添加订阅 → X」搜索框输入 displayName 或 username 模糊关键字，从候选结果里选——这是唯一的搜索入口。

### 能用 Open API / CLI 搜索或订阅 X 账号吗？

不能。**X 账号搜索与 X 订阅 / 取消订阅仅在 Web 控制台提供**，Open API 与 CLI 都不暴露这些写类端点。脚本场景的标准做法是：

1. 在 Web 控制台完成 X 账号搜索 + 订阅；
2. 再用 Open API `GET /open-api/subscriptions?sourceType=x` 列出已订阅 X 账号，并通过 `GET /open-api/x/{xUserId}/posts | /articles` 拉取内容。

### X 推文里的转推 / 引用 / 线程怎么呈现？

- **Open API**（`GET /open-api/x/{xUserId}/posts`）返回 **结构化原始字段**：`retweetedPost` / `quotedPost` 为对象或 null，`threadPosts` 为数组；适合脚本与自定义渲染消费；
- **Feed 公开层**（`/feed/{token}/{rss|atom|json}/x-posts/...`）返回**已渲染的 HTML 片段**，把转推 / 引用 / 线程合并到一条阅读单元里，方便阅读器直接呈现。

两条线职责互不重叠 —— 程序读 Open API、人读 Feed。

## Feed 相关

### Mp2RSS 支持哪些 Feed 格式？

支持 **RSS 2.0 / Atom 1.0 / JSON Feed 1.1 / OPML 2.0**。你可以按需选择，不同格式之间内容保持一致。

### 我能在阅读器里订阅"全部订阅合集"吗？

可以。所有格式都提供 `/all` 变体（公众号 + X 合并按时间线展示）：
- `/feed/<token>/rss/all`
- `/feed/<token>/atom/all`
- `/feed/<token>/json/all`

粘贴到阅读器即可看到所有订阅信息源的统一时间线。

### OPML 怎么下载？

访问 `/feed/<token>/opml` 默认在浏览器中直接渲染显示；在链接末尾加 `?download=1` 参数即可触发浏览器下载为 `.opml` 文件，便于导入其他 RSS 服务。

### Feed 链接多久刷新一次？

默认缓存 5 分钟，主流阅读器会按该 TTL 自行调度拉取。

### 为什么阅读器里突然有一条"会员已到期"的条目？

账户到期后（含试用到期）Feed 里会注入一条显眼的"会员已到期，请续费以恢复更新"提示，提醒你及时续费。该提示对公众号 Feed 与 X Feed 都生效。

## Feed 密钥

### Feed 密钥泄漏了怎么办？

立即登录控制台 → 「账户设置」 → **重置 Feed 密钥**。重置后旧链接**即时失效**，所有在外部阅读器里配置的旧链接都会失败，请用新链接重新订阅。

### Feed 密钥和 API 的 Bearer Token 是什么关系？

是同一个。Mp2RSS 的 Open API 与 CLI 都直接复用 Feed 密钥作为 `Authorization: Bearer` 凭据。用户在控制台重置 Feed 密钥的同时，也意味着旧的 API / CLI 调用凭据同步失效。

## 付费与计费

### 试用期和付费期有什么区别？

没有任何权益差别 —— 公众号 + X 全量信息源、全部 Feed 格式、Open API 与 CLI 均可使用。

### 怎么看我的剩余试用 / 会员时长？

登录控制台 → 「账户设置」，会显示试用剩余天数 / 会员有效期以及近期付费记录。

### 我转账完成后为什么会员没立即开通？

充值采用人工核对方式，需要少量处理时间。

### 我在有效期内续费会浪费剩下的时间吗？

不会。有效期内续费，新时长会**叠加**在当前到期时间之上；只有过期后续费才从续费当日起算。
